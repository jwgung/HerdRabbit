# HerdRabbit

[English](README.md) | 한국어

HerdRabbit은 현재 머신에서 실행 중인 [Herdr](https://herdr.dev/) 워크스페이스를 데스크톱과 모바일 브라우저에서 관리하는 개인용 웹 애플리케이션입니다. 기존 Herdr 세션에 연결해 상태와 터미널 출력을 확인하고, 입력과 제한된 특수 키를 전달합니다.

> [!IMPORTANT]
> HerdRabbit은 한 사람이 자신의 Herdr 세션에 접속하기 위한 **개인용 도구**입니다. 다중 사용자 계정, 권한 분리 또는 공개 호스팅을 위한 서비스가 아닙니다. 공인 인터넷에 직접 노출하지 말고 Tailscale 같은 사설 네트워크 안에서 사용하세요.

서버는 Node.js 표준 라이브러리, Web Push 전송용 `web-push`, WebAuthn 검증용 SimpleWebAuthn과 설치된 `herdr` CLI를 사용합니다. 앱, 저장소, systemd 서비스 이름은 모두 `HerdRabbit`입니다. 예전 `herdrabbit.service` 이름으로 설치된 환경은 설치 스크립트를 다시 실행하면 자동으로 이관됩니다.

HerdRabbit은 OS 사용자별로 실행하며, 선택적으로 인스턴스 비밀번호를 설정할 수 있습니다. 별도의 계정명은 사용하지 않습니다.

## 재사용 가능한 HTML UI

공통 UI는 [`public/ui`](public/ui/README.md)에 있습니다. 앱 실행 중 `/ui/index.html`에서 예제를 보거나, 폴더를 복사해 `index.html`을 직접 열 수 있습니다. 현재 앱과 같은 CSS를 사용하며 테마·버튼·입력·탐색/상태·메뉴·사이드바·대화상자를 제공합니다. 다른 프로젝트에서는 `ui/ui.css`만 연결하면 됩니다.

브라우저 검증: Playwright가 설치된 환경에서 `npm run check:ui` (필요하면 `PLAYWRIGHT_MODULE`에 모듈 경로 지정).

## 권장 접속 방식: Tailscale부터

HerdRabbit은 `127.0.0.1`에서만 수신하고, 원격 기기에서는 [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve)를 통해 접속하는 구성을 기준으로 설계했습니다.

```text
휴대폰·태블릿·PC의 PWA
        │ tailnet 내부 HTTPS
        ▼
Tailscale Serve
        │ 127.0.0.1:3xxxx로 HTTP 전달
        ▼
Herdr 머신의 HerdRabbit
```

Herdr가 실행되는 머신과 HerdRabbit을 여는 기기가 모두 같은 tailnet에 로그인되어 있어야 합니다. 생성되는 HTTPS 주소는 공개 웹사이트가 아니라 tailnet 전용 주소입니다. HerdRabbit 비밀번호는 추가 보호 수단이며 Tailscale을 대체하지 않습니다. 이 앱에는 Tailscale Funnel을 사용하지 마세요.

Tailscale이 설치되어 실행 중이면 [한 줄 자동 설치](#한-줄-자동-설치)가 머신의 Tailscale DNS 이름을 감지하고 허용 호스트와 같은 포트의 HTTPS Serve 규칙을 자동 등록합니다. 수동 설정과 문제 해결은 [Tailscale Serve로 HTTPS 제공](#tailscale-serve로-https-제공)을 참고하세요.

## 기능

- 기존 Herdr 워크스페이스, 탭, 패인 및 에이전트 상태 조회
- 현재 OS 사용자에게 등록된 여러 Herdr 영구 세션을 한 화면에서 조회
- 이 머신과 Connect PC로 붙인 PC의 모든 패인을 Herdr가 그리는 화면 그대로 표시(실제 `herdr terminal attach` + xterm.js). 전체 화면 TUI·커서·색이 같습니다. attach할 수 없는 패인은 같은 터미널에 읽기 전용으로 비춰 보여 줌
- Claude Code·Codex 패인을 채팅으로 읽기: 대화를 턴 단위로 보여 주고, 에이전트의 도구 호출은 "Worked for …" 한 줄 아래로 접으며, 위로 스크롤하면 이전 턴을 불러옵니다. 패인 머리글의 **Chat** / **Terminal** 전환(또는 `Ctrl`/`Cmd`+`J`)으로 아무것도 다시 연결하지 않고 오갑니다
- 멈춰서 묻는 에이전트(도구 승인, 질문, 메뉴)에 채팅 맨 아래 카드의 버튼으로, 또는 터미널 위 배너에서 답하기
- 패인마다 보내지 않은 초안을 따로 기억하고, 새로고침해도 유지합니다
- 선택한 패인에 텍스트 또는 셸 명령 전송
- 브라우저가 앱으로 전달하는 환경에서 `Ctrl+Tab`, `Ctrl+Shift+Tab`, `Ctrl+1`–`Ctrl+9`로 사이드바 항목 이동
- 앱 재실행 후에도 터미널 글자 크기와 패인별 최근 100개 전송 프롬프트 복원, 입력창의 위/아래 방향키로 기록 탐색
- `Esc`, `Ctrl+C`, `Tab`, `Shift+Tab`, 방향키 및 `Enter` 전송
- 기본 셸로 프로젝트와 세션 생성
- 확인 후 세션 또는 프로젝트 종료
- 프로젝트와 세션 이름 변경
- 이미지·동영상·오디오·마크다운·텍스트를 내려받지 않고 브라우저에서 바로 보기
- 이 머신을 포함한 모든 머신을 사이드바 줄에서 관리: 이름과 버전 확인, Connect PC로 붙인 PC는 이름 변경·끊기(포트를 옮긴 PC는 새 주소 찾기)
- 같은 행에서 머신이 쓰는 Claude Code·Codex 계정을 다시 로그인하지 않고 전환
- 공용 업로드 폴더를 통한 기기와 Herdr 머신 사이의 파일 전송: 입력창 옆 첨부 버튼으로 업로드, 저장된 경로를 입력창에 삽입, 저장된 파일 다운로드 및 삭제
- 프로젝트별 하위 세션 접기와 접힘 상태 저장
- 마지막으로 선택한 세션을 저장하고 새로고침 후 복원
- 확인하지 않은 완료(`✓`) 세션을 열면 현재 브라우저에서 `○`로 바뀜
- 사이드바에서 세션마다 실행 중인 프로그램(Claude, Codex, 다른 에이전트, 셸) 아이콘을 왼쪽에, 상태를 맨 오른쪽에 표시: Herdr 고유의 상태 기호(`◐` 작업 중, `×` 답이 필요함, `✓` 확인하지 않은 완료, `○` 대기). 접힌 프로젝트는 확인하지 않은 완료를 계속 강조
- 에이전트가 입력을 기다리거나 끝났을 때 프로젝트명·탭 이름과 짧은 상태만 표시하는 PWA 알림. 앱을 보는 중에는 앱 안에서 알림
- 데스크톱 접이식 사이드바와 모바일 오버레이 탐색기
- 라이트·다크 모드
- 터미널 출력과 입력창의 글자 크기 조절 및 설정 저장
- 데스크톱과 모바일에서 설치 가능한 PWA
- 선택형 인스턴스 비밀번호, Passkey 로그인, 7일 고정 만료, PWA를 새로 열 때 재로그인, 로그인된 브라우저 목록에서 하나씩 또는 모두 로그아웃
- 사용자별 systemd 서비스 및 충돌하지 않는 `30000–39999` 포트 자동 설치
- 설치 과정에서 Tailscale Serve HTTPS 자동 등록

패인 분할과 Herdr 영구 세션명 변경은 현재 제공하지 않습니다.

## 기술 구성

- Node.js 22 이상, ESM 및 표준 라이브러리 기반 HTTP 서버
- 프레임워크 없는 HTML, CSS, Vanilla JavaScript UI
- Web App Manifest와 Service Worker를 사용하는 설치형 PWA
- Push API, Service Worker와 VAPID 기반의 상태 알림
- `execFile` 인자 배열로 호출하는 로컬 Herdr CLI 어댑터
- 사용자별 `systemd --user` 서비스와 자동 포트 선택
- Tailscale Serve를 통한 tailnet 전용 HTTPS 프록시
- SimpleWebAuthn 기반 WebAuthn Passkey, `scrypt` 비밀번호 해시, HMAC 서명 세션, `HttpOnly` 쿠키, 창 단위 실행 토큰 및 CSRF/동일 출처 검증
- Node.js 내장 `node:test`, 가짜 Herdr 실행 파일을 사용한 단위·통합 테스트

현재 터미널의 입력·대화 전송·기능키와 화면 갱신은 `/api/terminal` WebSocket을 사용합니다. attach된 패인은 Herdr의 출력을 그대로 받고, 비춰 보이는 패인은 최초 화면 이후 변경된 부분만 받습니다. Herdr는 terminal attach 밖에서는 범용 화면 변경 구독을 제공하지 않아 서버가 변경을 감지합니다. 입력 직후·출력 변경 중에는 조회 완료 후 50ms, 조용할 때는 500ms 간격으로 확인하며 같은 패인·조회 범위의 구독은 공유합니다. 브라우저가 백그라운드로 가면 연결을 닫고 복귀 시 새 화면을 받습니다. 세션 상태는 Herdr의 `pane.agent_status_changed` 이벤트를 WebSocket으로 전달해 선택하지 않은 세션까지 갱신합니다. 프로젝트·세션 목록은 2초마다 HTTP로 조회하며, 상태 구독 연결 후에도 HTTP로 다시 동기화합니다. 상태 구독이 끊기면 HTTP 목록 조회로 보완하고 재구독합니다. 로그인·프로젝트·세션 관리는 HTTP를 유지합니다. 푸시 알림 동작은 유지합니다.

## 머신 추가

### HerdRabbit이 도는 다른 PC (Connect PC)

두 PC 모두 같은 tailnet에서 Tailscale이 켜져 있어야 합니다(꺼져 있으면 tailnet 주소가 없어 `HERDR_WEB_PEER_HOST`를 쓸 수 없고 `tailscale whois` 확인도 안 됩니다).

모든 PC는 같은 HerdRabbit을 돌립니다. [빠른 시작](#빠른-시작)으로 설치하면 PC마다 자기 화면과 로그인이 `127.0.0.1` + Tailscale Serve 뒤에 생깁니다. 여기에 더해 PC는 다른 PC를 위한 **Connect PC 포트**를 열 수 있습니다. 그러면 다른 PC의 HerdRabbit이 이 PC의 세션을 자기 화면에 함께 보여 줍니다. 방향은 한쪽입니다. A가 B를 붙이면 B는 A 화면에만 보이고, B는 그와 상관없이 자기 화면과 로그인을 그대로 가집니다.

**붙을 PC(B)에서:** Connect PC 포트를 열고 붙을 수 있는 PC를 정합니다. B에서 `npm run install-service`를 다시 실행해 "다른 PC가 이 PC에 붙을 수 있게 열까요?"에 답하고 tailnet 목록에서 허용할 PC를 고르거나, 직접 설정합니다.

| 변수 | 의미 |
| --- | --- |
| `HERDR_WEB_PEER_HOST` | 이 PC의 tailnet 주소(예: `100.64.0.2`). 설정하면 Connect PC 포트가 열리고, 기본값(설정 안 함)이면 닫혀 있습니다. Tailscale 대역(`100.64.0.0/10`, `fd7a:115c:a1e0::/48`)이나 loopback 주소만 받습니다. 모든 인터페이스(`0.0.0.0`, 어떤 표기의 `::`든)나 LAN 주소는 받지 않고, 그런 값이면 서비스가 시작하지 않습니다. |
| `HERDR_WEB_PEER_PORT` | 그 포트. 1024–65535 정수, 기본 `38788`. tailnet 주소의 화면 포트는 Tailscale Serve가 쓰므로 같은 포트를 쓸 수 없습니다. |
| `HERDR_WEB_PEER_ADDRESSES` | 붙을 수 있는 PC의 tailnet 주소, 쉼표로 구분. tailnet 주소(와 한 PC에서 시험할 때의 loopback)만 받습니다. |
| `HERDR_WEB_PEER_LOGINS` | 붙을 수 있는 tailnet 계정, 쉼표로 구분. 요청한 주소의 계정을 `tailscale whois`로 확인합니다. 두 목록을 함께 쓰면 둘 다 맞아야 합니다. |
| `HERDR_WEB_HUB` | 선택. 이 PC를 붙일 PC의 화면 주소(예: `https://laptop.tailnet.ts.net:38787`). 그 PC에 이 PC의 Connect PC 포트가 어디인지 알립니다. 기본 포트가 아닐 때만 필요합니다. |

허용 목록이 둘 다 비어 있으면 포트는 아무도 받지 않습니다.

**붙이는 PC(A)에서:** 사이드바 위 **+ → Connect PC**를 엽니다. tailnet의 PC를 나열하고 각각 어떤 상태인지 보여 줍니다: 연결 가능, 이미 추가됨, HerdRabbit은 있지만 이 PC를 허용하지 않음, 연결 규약이 다름, 붙을 것이 없음(Connect PC 포트 없음 또는 꺼짐 — 개수로만 접어 둠). 연결 가능한 PC를 고르거나 **Enter an address**를 펼쳐 Connect PC 주소(`http://100.64.0.2:38788`)를 직접 넣습니다. **Test connection**이 지금 입력한 값으로 성공해야 **Save**가 켜집니다. 양쪽 어디에도 이름과 주소 말고는 저장하지 않습니다. B는 요청이 들어온 주소로 A를 알아보므로 키나 비밀번호가 없습니다. 붙인 PC는 `~/.config/herdr-bridge/servers.json`(권한 `0600`, 또는 `HERDR_WEB_SERVERS_FILE`)에 저장되고, A를 쓰는 모든 브라우저가 함께 씁니다.

찾기는 기본 포트만 확인합니다. 다른 포트의 PC(같은 PC의 두 번째 계정 등)는 `HERDR_WEB_HUB`가 A를 가리키면 스스로 알리고, A는 찾은 PC 옆에 함께 보여 줍니다. 알림은 목록에 한 줄을 더할 뿐이고, 추가는 여전히 사람이 고르며 고를 때 그 주소를 다시 확인합니다. PC는 자기 자신만, 그리고 내 tailnet 계정에서만 알릴 수 있습니다. 알린 내용은 `~/.config/herdr-bridge/announced.json`에 남고, 확인해 보니 비어 있는 주소는 지우며, 개수에 상한이 있습니다.

**버전.** 두 PC는 **연결 규약(connection protocol)** 번호가 같으면 연결됩니다. 이 번호는 주고받는 내용이 바뀔 때만 바뀌므로 HerdRabbit 버전은 달라도 되고, 두 버전은 Details에 함께 보입니다. 연결 규약이 다른 PC는 offline으로 표시하고, 상태와 Details에 두 PC의 연결 규약과 HerdRabbit 버전을 함께 적어 어느 쪽을 업데이트할지 알 수 있게 합니다.

붙인 PC의 줄 메뉴에는 **Details**(종류, 주소, 이 PC와 나란히 본 HerdRabbit 버전, 연결 규약, Herdr 버전), **AI accounts**, **Rename**, **Disconnect**가 있고, offline인 동안에는 **Find new address**가 생깁니다. 포트를 옮긴 PC도 tailnet 주소는 그대로이므로 다시 찾아보고 다른 포트에서 답하면 주소를 바꿔 둡니다. 이 PC 자신의 Details에는 Connect PC 주소와 허용한 PC 수가 나옵니다.

지금 붙인 PC로 되는 것: 프로젝트·세션·패인 목록과 에이전트 상태(B에서 스트림으로 받음), 패인을 실제 터미널로 attach(입력·크기 조절·휠 스크롤 포함)하고 **찾기**로 B의 Herdr 이전 기록 전체 검색, 패인에 텍스트·키 보내기, B에서 프로젝트·세션 만들기·이름 바꾸기·닫기·끌어서 순서 바꾸기, Files 탭과 업로드(B의 디스크), 경로 링크로 B의 파일 열기, 질문 카드로 B의 에이전트에 답하기(Claude 계획·질문 카드의 글 전체는 B의 대화 기록에서), **Chat**으로 B의 Claude·Codex 패인 읽기, **AI accounts**로 B의 로그인을 B에서 전환. 이전 버전 HerdRabbit이 도는 PC는 패인을 읽기 전용으로 비춰 보이고, 찾기는 버전이 낮다고 알려 주며, Chat 버튼은 그 PC를 업데이트하라고 안내합니다. 그 PC를 업데이트하세요.

붙인 PC의 패인은 그 PC에서 attach합니다. B가 자기 화면에서와 똑같이 자기 가상 터미널에서 `herdr terminal attach`를 돌리고, A는 B의 Connect PC 포트에 연 WebSocket 하나로 그것을 중계합니다. A의 브라우저들은 이 패인을 로컬 패인처럼 함께 씁니다(늦게 연 브라우저는 최근 화면을 받고, 크기는 마지막으로 열거나 입력한 브라우저가 정하며, 다른 클라이언트가 잡고 있으면 **Open here**). A는 B의 Herdr 실행 파일이나 소켓을 알지 못합니다. 패인에 어느 터미널이 있는지 묻고, B에게 그것을 attach해 달라고 할 뿐입니다. node-pty가 없는 PC나 이 기능 이전의 HerdRabbit을 쓰는 PC는 예전처럼 패인을 비춰 보여 줍니다. B의 패인을 위해 A에 node-pty가 있을 필요는 없습니다.

### Herdr SSH 머신 (제거됨)

이전 버전은 Herdr 자체의 SSH 머신(`herdr machine add`)도 이 머신과 나란히 보여 줬습니다. 이 기능은 Connect PC로 대체되어 제거되었습니다. Connect PC는 상대 PC에서 직접 터미널 attach, 찾기, 채팅, 질문 카드, 파일 탐색, AI 계정 전환을 처리합니다. 그런 PC를 다시 쓰려면 그 PC에 HerdRabbit을 설치하고 **+ → Connect PC**로 추가하세요. HerdRabbit은 Herdr의 머신 목록을 건드리지 않으며, 목록에 머신이 남아 있는 동안 페이지가 브라우저마다 한 번 이 안내를 보여 줍니다.

### 모든 머신을 한 사이드바에

모든 머신이 **머신 → Herdr 세션 → 프로젝트 → 탭/패인**으로 함께 표시되고, 패인을 고르면 그 머신에 입력이 가고 출력이 읽힙니다. 머신마다 따로 갱신하고 실패하면 재시도 간격을 늘리므로, 닿지 않는 머신이 로컬 데이터를 지연시키지 않습니다. 장애 중에도 마지막으로 알려진 패인은 남고 그 머신은 offline으로 표시됩니다. 프로젝트/세션 선택에 그 머신의 세션이 나타나고, 거기서 프로젝트와 탭을 만들고 이름을 바꾸고 닫을 수 있습니다.

머신은 보이는 자리에서 관리하고, 모든 머신에 줄이 있습니다. 이 머신 하나뿐이어도 마찬가지입니다. `⋯` 메뉴의 **Details**로 머신 이름, 이 머신에서 답하는 HerdRabbit 버전, 그 머신의 Herdr 버전(0.9.0보다 낮으면 표시하고, 이 머신은 서버 시작 로그에도 경고), 그 머신이 내주는 Herdr 세션과 패인 수를 보고, **AI accounts**를 엽니다. 브라우저 전체에 걸린 설정(**Passkeys**, **Signed-in devices** 포함)은 여기가 아니라 사이드바 아래의 ⚙ 설정 메뉴에 있습니다. 머신이 연결되지 않을 때 가장 먼저 볼 것이 Details입니다.

### 이전 버전에서 leaf로 설치한 PC

이전 버전도 같은 방식으로 PC를 붙였지만, 붙는 PC를 "leaf"라 부르고 자기 화면 없이 허브에만 답하게 했습니다(`HERDR_WEB_ROLE=leaf`). 그런 유닛은 계속 동작합니다. leaf의 주소와 포트가 그대로 Connect PC 포트가 되므로 그 PC를 저장해 둔 허브는 계속 연결되고, `127.0.0.1`에 자기 화면이 생깁니다. leaf에는 비밀번호가 없었으므로, 비밀번호를 정할 때까지 그 화면은 비밀번호를 설정하라는 503 응답만 돌려줍니다(Connect PC 포트는 그대로). 그 PC에서 `npm run install-service`를 실행하면 비밀번호가 있는 일반 유닛으로 다시 쓰고, Connect PC 포트와 허용한 PC를 유지할지 묻습니다. 설치 스크립트는 이때 포트를 화면 포트(이후 Tailscale Serve가 쓰는 포트)에서 옮기므로, 허브에서 **Find new address**를 한 번 누르세요. `tailscale serve` 뒤 loopback에 있던 leaf는 그 방식으로 더 이상 닿지 않으니 위처럼 Connect PC 포트를 여세요.

## 구조

```text
브라우저 / 설치된 PWA
        │
        │ HTTPS (선택 사항)
        ▼
Tailscale Serve
        │
        │ http://127.0.0.1:3xxxx
        ▼
HerdRabbit Node.js 서버
        │
        │ execFile 인자 배열
        ▼
로컬 herdr CLI ── default 및 이름 있는 Herdr 영구 세션
                         └─ 워크스페이스와 패인
```

프로젝트 생성은 Herdr 워크스페이스를, 세션 생성은 해당 워크스페이스의 새 탭과 기본 셸을 만듭니다. HerdRabbit 자체가 별도의 터미널 서버를 운영하지는 않으며, 화면과 입력은 Herdr 패인에 연결됩니다.

### 여러 Herdr 영구 세션

HerdRabbit은 `herdr session list --json`으로 **서비스를 실행한 OS 사용자의** 영구 세션을 찾습니다. 실행 중인 `default` 및 이름 있는 세션의 snapshot을 각각 가져와 합치며, 같은 `w1:p1` 로컬 ID가 여러 세션에 있어도 충돌하지 않도록 내부적으로 세션 범위 ID를 붙입니다. 입력, 출력, 이름 변경, 생성과 종료 명령은 원래 Herdr 세션으로 다시 라우팅됩니다.

- Herdr 영구 세션이 하나뿐이면 기존처럼 별도 구분 없이 표시됩니다.
- 둘 이상이거나 접근할 수 없는 세션이 있으면 사이드바에 Herdr 세션별 그룹과 상태가 표시됩니다.
- 중지된 영구 세션은 상태만 표시하고 snapshot은 요청하지 않습니다.
- 새 프로젝트는 현재 선택한 패인이 속한 Herdr 세션에 생성됩니다. 선택이 없으면 실행 중인 기본 세션, 그다음 첫 실행 세션 순으로 선택합니다.
- 다른 OS 사용자의 세션과 `herdr --no-session`으로 실행한 일회성 인스턴스는 가져오지 않습니다.

### 여러 OS 사용자

각 Linux 사용자는 자신의 계정에서 설치 스크립트를 실행합니다. `systemd --user` 서비스 이름은 사용자 영역별로 분리되므로 모두 `herdrabbit.service`를 사용해도 충돌하지 않습니다. 설치 스크립트는 로컬 수신 포트와 기존 Tailscale Serve HTTPS 포트를 검사한 뒤 `30000–39999` 범위에서 비어 있는 포트를 선택합니다.

```text
alice → 127.0.0.1:38787 → https://server.example.ts.net:38787
bob   → 127.0.0.1:30000 → https://server.example.ts.net:30000
```

각 서비스는 서비스를 실행한 Linux 사용자의 Herdr와 설정 파일만 사용합니다. 기존 서비스를 다시 설치하면 이미 배정된 포트를 유지합니다.

## 요구 사항

- Linux 또는 macOS
- Node.js 22 이상
- 실행 가능한 `herdr` CLI 0.9.0 이상. 없으면 자동 설치 스크립트가 설치하고, 낮으면 설치 스크립트와 `update.sh`가 `herdr update --handoff`로 올립니다. 실행 중인 패인은 끊기지 않습니다.
- 실행 중인 Herdr 영구 세션 하나 이상
- 원격 HTTPS 접속이 필요하면 Tailscale
- 백그라운드 상태 알림을 사용하려면 브라우저 푸시 서비스로 나가는 인터넷 연결

버전을 확인합니다.

```bash
node --version
herdr --version
herdr status server
```

Herdr만 먼저 직접 설치하려면 공식 설치 스크립트를 실행합니다.

```bash
curl -fsSL https://herdr.dev/install.sh | sh
```

기본 설치 위치는 `~/.local/bin/herdr`입니다. 새 터미널을 열어도 명령을 찾지 못한다면 셸 설정에 다음을 추가합니다.

```bash
export PATH="$HOME/.local/bin:$PATH"
```

## 빠른 시작

### 한 줄 자동 설치

Linux에서 실행합니다. macOS에서는 아래의 직접 실행 방법을 사용해야 합니다.

```bash
curl -fsSL https://raw.githubusercontent.com/ultivis-iot/HerdRabbit/main/install.sh | sh
```

스크립트는 `~/.local/share/herd-rabbit`에 저장소를 복제하거나 업데이트한 뒤 아래의 서비스 설치 절차를 실행합니다. 기존 설치 경로에 수정 사항이 있으면 덮어쓰지 않고 중단합니다. `HERD_RABBIT_INSTALL_DIR`로 설치 경로를 바꿀 수 있습니다.

### 저장소에서 수동 설치

```bash
gh repo clone ultivis-iot/HerdRabbit
cd HerdRabbit
npm ci --omit=dev
npm run install-service
```

설치 중 HerdRabbit 비밀번호를 숨김 입력으로 묻습니다.

```text
HerdRabbit 비밀번호 (비워 두면 사용 안 함):
비밀번호 확인:
```

- 비밀번호를 입력하면 웹 접속 시 비밀번호 화면이 표시됩니다.
- 아무것도 입력하지 않고 `Enter`를 누르면 비밀번호 인증 없이 설치됩니다.
- `herdr` 명령이 없으면 공식 `https://herdr.dev/install.sh`를 내려받아 `~/.local/bin/herdr`에 자동 설치합니다. 0.9.0보다 낮으면 `herdr update --handoff`로 올리고, 그래도 낮으면 설치를 중단합니다.
- Tailscale이 실행 중이면 DNS 이름을 자동으로 허용하고 같은 포트의 HTTPS Serve를 등록합니다.
- `sudo tailscale serve` 실행을 위해 설치 도중 sudo 비밀번호를 물을 수 있습니다.
- 설치 완료 시 선택된 포트와 최종 HTTPS 주소를 출력합니다.

Tailscale이 없거나 실행 중이 아니면 서비스 설치까지만 완료하고 HTTPS 등록은 건너뜁니다.

### 직접 실행

서비스 설치 없이 현재 터미널에서 실행할 수도 있습니다.

```bash
npm ci --omit=dev
npm start
```

직접 실행의 기본 주소는 다음과 같습니다.

```text
http://127.0.0.1:38787
```

한 줄 설치 스크립트는 Web Push와 WebAuthn 런타임 의존성을 자동 설치합니다. 저장소를 직접 복제했거나 업데이트했다면 `npm ci --omit=dev`를 실행하세요.

### Herdr 플러그인으로 설치

HerdRabbit을 [Herdr 플러그인](https://herdr.dev/)으로도 설치할 수 있습니다 (Herdr 0.9.0 이상, `PATH`에 Node.js 22+와 npm 필요).

```bash
herdr plugin install ultivis-iot/HerdRabbit
```

- **빌드:** 설치를 확인하면 Herdr가 자신이 관리하는 플러그인 체크아웃에서 `npm ci --omit=dev`를 실행합니다.
- **시작:** Herdr가 시작할 때마다(라이브 핸드오프 뒤 포함) 이미 응답하는 HerdRabbit이 없으면 백그라운드로 HerdRabbit을 띄웁니다. systemd 서비스(`herdrabbit.service` 또는 이전 이름 `herdr-web-local.service`)가 실행 중이면 아무것도 하지 않으므로 둘이 함께 돌지 않습니다.
- **액션:** `herdr plugin action invoke herdrabbit.start`, `herdrabbit.stop`, `herdrabbit.status`, `herdrabbit.restart`. stop은 플러그인이 직접 띄운 서버만 멈추고 systemd 서비스는 건드리지 않습니다. `herdr plugin update` 뒤에도 서버가 이전 체크아웃에서 돌고 있으면 status가 알려 주니 restart하세요.
- **연결 패인:** `herdr plugin pane open --plugin herdrabbit --entrypoint connect`는 페이지 주소(이 PC 주소와, 포트를 전달하는 Tailscale Serve HTTPS 주소가 있으면 그 주소), 비밀번호 설정 여부, 설정 방법을 보여 줍니다. `qrencode`가 설치돼 있으면 휴대폰 주소의 QR 코드도 그립니다.
- **비밀번호:** `herdr plugin pane open --plugin herdrabbit --entrypoint password`가 숨김 입력으로 비밀번호를 묻고 플러그인 서버를 다시 시작합니다. 비밀번호는 플러그인 설정 파일에 저장되지 않습니다.
- **설정:** `herdr plugin config-dir herdrabbit`이 `.env`가 있는 폴더를 알려 줍니다. 첫 시작 때 주석만 있는 템플릿으로 만들어집니다. [환경 변수](#환경-변수)의 `HERDR_WEB_*`와 `HERDR_BIN`을 한 줄에 하나씩 `KEY=VALUE`로 적고 restart하세요. 서버 로그와 pid 파일은 체크아웃이 아니라 플러그인 상태 폴더에 둡니다.

Linux에서는 [한 줄 자동 설치](#한-줄-자동-설치)의 systemd 서비스가 여전히 권장 경로입니다. Herdr 없이도 로그인 때 시작하고 Tailscale Serve도 등록해 줍니다. 서비스 설치기는 Linux 전용이므로 macOS에서는 이 플러그인으로 HerdRabbit을 띄우면 됩니다. 어느 쪽이든 휴대폰에서는 Tailscale Serve로 접속합니다. [Tailscale Serve로 HTTPS 제공](#tailscale-serve로-https-제공)을 보세요.

## 비밀번호와 Passkey 인증

비밀번호는 HerdRabbit 인스턴스별로 하나만 사용하며 계정명은 입력하지 않습니다. Linux 계정은 서비스를 실행한 사용자로 결정됩니다.

비밀번호를 변경하거나 잊어버렸다면 해당 Linux 계정으로 SSH 접속한 뒤 저장소에서 실행합니다.

```bash
cd ~/.local/share/herd-rabbit
npm run password
```

새 비밀번호를 두 번 입력하면 즉시 교체됩니다. 첫 입력을 비워 두면 비밀번호 인증이 해제됩니다. 설치된 서비스가 실행 중이면 자동으로 재시작하므로 기존 로그인 세션과 등록된 Passkey도 모두 무효화됩니다.

비밀번호 원문은 저장하지 않습니다. `scrypt`로 만든 해시, 브라우저 세션 서명용 난수와 Passkey 공개 정보만 다음 파일에 `0600` 권한으로 저장합니다.

```text
~/.config/herdr-bridge/auth.json
```

로그인 세션의 고정 만료 시간은 7일입니다. 브라우저의 `HttpOnly`, `SameSite=Strict` 쿠키와 현재 창의 `sessionStorage`에 분리된 서명 토큰이 모두 있어야 API를 사용할 수 있으며, HTTPS 접속에서는 쿠키에 `Secure` 속성도 적용됩니다. PWA나 탭을 완전히 닫았다가 새로 열면 창 토큰이 없어 Passkey 또는 비밀번호로 다시 로그인해야 합니다. 같은 창의 새로고침과 백그라운드 복귀에서는 로그인이 유지됩니다. 인증 파일이 없으면 인증을 요구하지 않습니다.

사이드바 아래 ⚙ 설정 메뉴의 **Signed-in devices**(비밀번호가 설정돼 있을 때 표시)를 열면 로그인된 브라우저를 브라우저·시스템 이름과 로그인·마지막 사용 시각으로 보여 줍니다. 목록은 최근 64개까지이며, 그보다 많이 로그인하면 가장 오래된 로그인이 끝납니다. 같은 브라우저에서 다시 로그인하면 줄이 늘지 않고 그 브라우저의 이전 항목을 대신합니다. **Sign out**은 하나를 끝내며 그 브라우저의 열린 터미널도 바로 닫힙니다. **Sign out everywhere**는 이 브라우저를 포함해 모두 끝냅니다. 접근을 빼앗기만 하므로 비밀번호를 묻지 않습니다. `(this device)`로 표시된 줄의 **Sign out**은 이 브라우저의 세션을 끝냅니다. 이 브라우저가 목록이 생기기 전에 로그인해 줄이 없으면 아래쪽 **Sign out this device**가 같은 일을 합니다. 인증 파일에는 토큰이 아닌 세션 해시만 남습니다. 목록이 생기기 전에 로그인한 세션은 만료될 때까지 유효하고 목록에는 나오지 않으며, **Sign out everywhere**로 함께 끝낼 수 있습니다.

틀린 비밀번호는 호출한 쪽별로 셉니다. 기준은 Tailscale Serve가 알려 주는 Tailscale 로그인이나 전달 주소, 또는 접속 주소입니다. 한 기기에서 틀리면 그 기기만 최대 15분 잠기고, 전체 호출에 대한 느슨한 상한은 따로 있습니다.

브라우저가 WebAuthn을 지원하면 첫 비밀번호 로그인 뒤 Passkey 등록을 안내합니다. 로그인하고 5분 안에는 그 창에서 비밀번호를 다시 입력하지 않고 Passkey 하나를 등록할 수 있고, 그 뒤에는 비밀번호를 묻습니다. 등록 후 로그인 화면에는 비밀번호와 **Passkey로 로그인**이 함께 표시됩니다. 기기에 따라 Face ID, 지문, Windows Hello, 기기 PIN, 보안 키 또는 다른 기기의 QR 인증을 사용할 수 있습니다. 생체 정보와 개인키는 기기 인증장치 밖으로 나오지 않으며 HerdRabbit은 credential ID, 공개키, 서명 카운터, 전송 정보와 아래 목록에 보이는 이름·날짜만 저장합니다. Passkey는 등록할 때 사용한 호스트 이름에 묶이므로 주소를 번갈아 쓰지 말고 고정된 Tailscale HTTPS 주소를 사용하세요.

⚙ 설정 메뉴의 **Passkeys**는 등록된 Passkey를 이름으로 보여 줍니다. 추가한 날, 마지막으로 쓴 날, 기기 사이 동기화 여부도 함께 나옵니다. 이름은 등록한 브라우저에서 정합니다(예: `Safari · iOS`). 이 목록이 생기기 전에 등록한 Passkey는 날짜 없이 `Passkey`로 나옵니다. 삭제하거나 새로 추가할 때는 비밀번호를 다시 입력합니다. 브라우저 세션을 훔친 사람이 그 세션보다 오래 남는 Passkey를 심어 두지 못하게 하려는 것입니다. Passkey를 삭제하면 삭제한 브라우저를 뺀 다른 모든 기기가 로그아웃됩니다. Passkey를 지우는 흔한 이유가 기기 분실이고, 그 기기가 아직 로그인돼 있을 수 있기 때문입니다. 다른 곳에 열린 터미널은 15초 안에 끊깁니다. 마지막 하나를 지워도 비밀번호 로그인은 남습니다. 목록과 삭제는 WebAuthn 없이도 되므로, 분실한 기기의 Passkey를 어느 브라우저에서든 지울 수 있습니다. 목록에는 이름과 날짜만 나오며 credential ID와 공개키는 인증 파일 밖으로 나가지 않습니다. 모든 Passkey를 한 번에 지우려면 `npm run password`를 실행합니다.

## 사용법

### 세션 선택과 저장

사이드바에서 에이전트 또는 패인을 선택하면 출력이 콘텐츠 영역에 표시됩니다. 마지막 선택은 브라우저 `localStorage`에 저장되며 같은 주소로 다시 접속하거나 새로고침하면 복원됩니다.

여러 Herdr 영구 세션이 등록되어 있으면 사이드바에서 먼저 Herdr 세션명으로 구분한 뒤, 그 아래에 프로젝트와 탭을 표시합니다. 여기서 Herdr **영구 세션**은 독립 서버/소켓 단위이고, 프로젝트 아래의 **세션**은 Herdr 탭 단위입니다.

브라우저 저장소는 출처별로 분리되므로 `http://192.168.x.x:38787`과 `https://server.example.ts.net`은 서로 다른 선택 상태를 가집니다. 저장된 패인이 더 이상 존재하지 않으면 첫 번째 패인을 선택합니다.

백그라운드 작업이 완료된 세션은 오른쪽 끝의 `✓`로 표시됩니다. 해당 세션을 열어 출력을 확인하면 현재 브라우저에서는 확인한 완료 이벤트를 기록하고 `○`로 바꿉니다. 이후 같은 세션에서 새로운 작업이 완료되면 `state_change_seq`가 달라지므로 다시 `✓`가 표시됩니다. 이 동작은 데스크톱 Herdr의 포커스를 강제로 바꾸지 않습니다.

### 상태 알림

사이드바 하단 ⚙ 설정 메뉴의 **Notifications**(켜짐·꺼짐·차단됨 표시)로 현재 브라우저나 설치된 PWA의 상태 알림을 켜거나 끕니다. 알림 권한은 이 항목을 눌렀을 때만 요청합니다.

- 알림 제목은 `프로젝트명 · 탭 이름`입니다. 서버를 둘 이상 연결했으면 서버 이름이 앞에 붙습니다.
- 완료와 입력 대기만 짧은 상태 문구로 알립니다. 유휴 상태로 돌아가거나 상태를 알 수 없을 때는 알리지 않습니다.
- HerdRabbit 창이 앞에 있으면 시스템 알림을 띄우지 않습니다. 보고 있는 패인은 조용히 넘어가고, 다른 패인의 알림은 앱 상단 배너와 짧은 소리로 알립니다. 배너를 누르면 그 패인이 열리고, 좌우나 위로 밀면 닫힙니다. 짧게 끌면 제자리로 돌아갑니다.
- 같은 상태 이벤트는 한 번만 알리고, 같은 세션의 이전 알림은 최신 상태로 교체합니다. 알림을 누르면 설치된 PWA를 열거나 활성화한 뒤 해당 세션을 복원합니다.

PWA나 탭을 닫은 상태에서도 알림을 받기 위해 표준 Web Push를 사용합니다. Firebase 프로젝트나 FCM SDK는 필요하지 않습니다. iPhone과 iPad에서는 iOS/iPadOS 16.4 이상에서 HerdRabbit을 홈 화면에 추가한 뒤 알림을 허용해야 합니다.

VAPID 키와 기기별 Push 구독은 다음 파일에 `0600` 권한으로 저장됩니다.

```text
~/.config/herdr-bridge/push.json
```

프로젝트명과 탭 이름은 잠금 화면 알림에 표시될 수 있습니다. 이전 명령과 작업 요청 내용은 표시하지 않습니다. 개인 기기에서만 알림을 허용하세요.

### 이름 변경과 접기

- 프로젝트명 오른쪽 `⋯` 메뉴에서 **이름 변경**을 누르면 이름을 편집합니다.
- 세션 오른쪽 `⋯` 메뉴의 **이름 변경**도 같은 방식으로 그 자리에서 편집합니다.
- `Enter` 또는 체크 버튼으로 저장합니다.
- `Esc` 또는 X 버튼으로 취소합니다.
- 프로젝트명 왼쪽 화살표로 하위 세션을 접거나 펼칩니다.
- 세션을 끌어 프로젝트 안에서 순서를 바꾸거나, 같은 머신·같은 Herdr 세션의 다른 프로젝트에 놓아 옮깁니다(이름은 유지됩니다). 분할된(패인 여럿) 세션은 프로젝트 안에서만 순서를 바꿀 수 있습니다. 프로젝트 이름을 끌면 프로젝트 순서가 바뀝니다. 폰에서는 줄을 잠깐 누르고 있다가 끌고, 짧게 누르면 지금처럼 선택되고 밀면 스크롤됩니다. 순서 바꾸기는 Herdr의 `tab.move`·`workspace.move`, 옮기기는 `pane move`를 씁니다.
- 서버와 Herdr 세션도 같은 방식으로 접힙니다. 머신이 여러 대인 사이드바를 지금 쓰는 하나로 좁힐 수 있고, 접힌 상태는 브라우저별로 기억합니다.
- 프로젝트를 접어도 현재 보고 있는 세션은 변경되지 않습니다.
- 접힘 상태는 같은 브라우저 주소의 `localStorage`에 저장됩니다.

세션은 이름을 주기 전까지 그 안에서 돌고 있는 에이전트를 보여줍니다. 그건 이름이 아닙니다 — 에이전트가 바뀌면 같이 바뀌고, 같은 에이전트를 쓰는 두 세션이 똑같이 읽힙니다. 이름을 주면 에이전트가 있던 자리를 이름이 가져가고 에이전트는 상태 옆으로 물러납니다. 패인이 여럿인 세션은 버튼마다 반복하지 않고 이름을 묶음 위에 둡니다.

상태 글자(`idle`, `working`)는 세션 옆에 적지 않습니다. 오른쪽 끝의 표식(`◐` 작업 중, `×` 답을 기다림, `✓` 확인하지 않은 완료, `○` 대기. 상태마다 색이 다름)이 이미 상태를 말하고, 행에는 상태 색 테두리가 없으며 선택한 행만 배경이 옅게 칠해집니다. 이름과 다르면 이름 아래 줄에 세션이 실행 중인 폴더가 나옵니다. 정확한 상태가 필요하면 세션에 마우스를 올리거나 스크린리더로 읽으면 글자로 나옵니다.

이름을 비우면 다시 떼어낼 수 있고, 세션은 에이전트를 다시 보여줍니다. Herdr에는 이름 없는 탭이 없어서 — `tab rename`은 라벨을 요구합니다 — 지우기는 탭이 처음 받은 번호를 되돌려 씁니다. 사이드바가 숨기는 값입니다.

프로젝트 이름 변경은 Herdr의 `workspace rename`, 세션 이름 변경은 `tab rename` 명령에 전달됩니다. 둘 다 그 머신 앞에 앉은 사람이 실행하는 것과 같은 명령입니다.

### 프로젝트와 세션 생성·종료

- 위쪽 `+` → **New project**로 이름을 지정한 새 프로젝트와 기본 셸을 만듭니다. 고른 패인의 Herdr 세션에 열리고, 세션 목록에 모든 머신의 실행 중인 세션이 나오므로 다른 머신에도 만들 수 있습니다.
- 프로젝트명 오른쪽 `⋯` 메뉴의 **새 세션**은 그 프로젝트에 기본 셸 세션을 하나 추가합니다.
- 세션 오른쪽 `⋯` 메뉴의 **이름 변경**은 그 세션의 이름을, **세션 종료**는 해당 Herdr 탭을 종료합니다.
- 프로젝트의 `⋯` 메뉴에 있는 **프로젝트 종료**는 그 아래의 모든 세션을 종료합니다.
- 종료는 실행 중인 프로세스에도 영향을 주므로 확인 대화상자를 거친 뒤 실행합니다.

생성된 셸에서는 `cd`, `codex`, `claude` 등 필요한 명령을 직접 실행하면 됩니다. 생성 명령은 현재 데스크톱 Herdr의 포커스를 바꾸지 않도록 `--no-focus`로 호출되며, 웹 화면에서는 새로 생성한 세션을 선택합니다.

### 터미널

이 머신의 패인은 attach해서 보여 줍니다. 서버가 패인마다 `herdr terminal attach` 하나를 가상 터미널(node-pty)로 띄우고, 열어 둔 브라우저들이 함께 씁니다. 입력은 바로 그 터미널로 가고, 터미널 크기는 그 패인을 마지막으로 열었거나 입력한 브라우저에 맞추고(다른 브라우저는 그 크기를 그대로 보여 줍니다), 휠이나 손가락으로 끌면 Herdr의 이전 기록이 스크롤되며 튕기면 관성으로 이어집니다. 나중에 연 브라우저는 최근 화면을 받습니다. 다른 클라이언트(다른 웹 브리지)가 이미 그 패인의 attach를 잡고 있으면 그렇다고 알려 주고, **Open here**를 누르면 가져옵니다. 누르지 않으면 몇 초마다 다시 시도해 그쪽이 놓으면 연결됩니다. Connect PC로 붙인 PC의 패인도 같은 방식으로, 그 PC에서 attach합니다([HerdRabbit이 도는 다른 PC](#herdrabbit이-도는-다른-pc-connect-pc) 참고). node-pty를 불러오지 못하거나 Herdr가 attach를 받아 주지 않는 패인은 같은 터미널에 비춰 보여 줍니다. 서버가 조회한 화면을 바뀔 때마다 그 자리에 다시 그립니다. 비춰 보이는 패인은 키 입력을 받지 않는 읽기 전용이고, 입력창과 기능키로는 그대로 보낼 수 있습니다. attach가 가능해지면 스스로 다시 연결합니다.

터미널이 살아 있지 않으면 터미널 위쪽 띠가 이유를 알려 줍니다. "Disconnected from HerdRabbit — retrying in 4s"(서버가 재시작했거나, 네트워크가 끊겼거나, 휴대폰이 잠들었을 때), "Herdr is not answering", "This pane is gone", Connect PC가 꺼져 있거나 이 PC를 허용하지 않거나 버전이 낮을 때, "Sign-in expired — reload to sign in again" 같은 식입니다. 다시 시도해서 나아질 수 있는 경우에는 **Reconnect** 버튼이 나오고, 누르면 다음 재시도를 기다리지 않고 바로 다시 연결합니다. 비춰 보이기만 하는 패인은 버튼 없이 조용히 알려 줍니다("Shown read-only: this PC can't attach terminals"). 평소 연결 중에는 3초쯤 넘게 걸리지 않는 한 아무것도 보이지 않고, 터미널이 다시 살아나면 띠는 바로 사라집니다. 다른 클라이언트가 잡고 있는 패인은 이 띠 대신 기존 **Open here** 띠를 보여 주고, Chat 화면에는 나타나지 않습니다.

### 채팅

Claude Code나 Codex가 돌고 있는 패인은 채팅으로도 읽을 수 있습니다. 패인 머리글의 **Chat**과 **Terminal**(또는 `Ctrl`+`J`, Mac은 `Cmd`+`J`)로 한 번에 전환합니다. 터미널 안에서는 `Ctrl`+`J`가 프로그램의 키로 남으므로 입력창에서 누르세요. 두 화면은 같은 자리에 있고 전환은 한쪽을 숨기고 다른 쪽을 보일 뿐이라, 터미널 attach는 유지되고 입력창의 초안도 그대로이며 각 화면의 스크롤 위치도 기억합니다. 터미널을 쓰지 않고 채팅에 5분 머물면 자원을 아끼려고 터미널 연결을 놓고, 다시 터미널로 돌아오면 attach해서 Herdr가 화면을 다시 그립니다.

채팅은 그 패인 에이전트의 대화 파일을 이 머신에서 읽어 턴으로 그립니다. Claude Code는 `~/.claude/projects` 아래에 쓰는 기록, Codex는 `~/.codex/sessions`(또는 `$CODEX_HOME`) 아래에 쓰는 rollout입니다. Claude 패인은 herdr가 알린 세션의 기록에서 시작해, 그 세션이 이어진 곳을 따라갑니다. 이어진 곳은 resume으로 넘어간 세션(`continued-in`)이거나, 그 세션에서 연 백그라운드 작업입니다. 백그라운드 작업은 짧은 id로 `~/.claude/jobs/<id>/state.json`(`CLAUDE_CONFIG_DIR`이 설정되어 있으면 그 디렉터리 아래)에서 찾습니다. 그 가운데 파일이 있는 가장 나중 것을 보여 주므로, 백그라운드 작업(`⑂`)을 띄운 패인은 그 작업의 대화를 보여 줍니다(이 머신만). Codex 패인의 rollout은 herdr가 그 패인에 알린 내용(rollout 경로나 thread id, thread id는 Node.js에 `node:sqlite`가 있으면 Codex의 thread 색인 `state_*.sqlite`에서, 없으면 파일 이름으로 찾음), 그 패인의 Codex 프로세스가 열어 둔 rollout, 마지막으로 그 디렉터리의 최근 thread 가운데 패인 화면에 답이 보이는 것 순서로 찾습니다. Codex가 넣는 지침·환경 정보와 암호화된 추론은 보이지 않고, 추론 요약은 Claude의 생각처럼 접히며, 압축(compaction)된 자리는 표시됩니다. 내 프롬프트는 말풍선, 답은 Markdown으로 보이고, 그 사이에 에이전트가 한 일(명령, 편집, 읽기, 생각)은 "Worked for 12s · 2 edits · 1 command" 한 줄 아래로 접혀 있다가 열면 호출마다 입력·diff·출력을, 요청하면 전체 출력을 보여 줍니다. 명령 줄에는 **View in terminal**이 있습니다. 파일 경로는 터미널에서처럼 누르면, 뷰어가 보여줄 수 있는 파일은 뷰어로, 그 밖의 파일은 Files 탭의 그 폴더로 엽니다. 위로 스크롤하면 이전 턴을 불러오고, 맨 아래에 있을 때는 새 턴을 따라갑니다. Markdown은 안전하게 그립니다. 모든 글자를 이스케이프하고 링크는 http(s)와 mailto만 만듭니다. 채팅이 화면에 있는 동안만 터미널 소켓으로 변경 알림을 받고, 읽을 때마다 `If-None-Match`를 보내므로 바뀌지 않은 대화는 비용이 거의 없습니다.

Connect PC로 붙인 PC(B)의 패인은 B가 직접 읽습니다. B는 자기 페이지에서와 똑같이 자기 대화 기록을 찾아 읽고(Codex rollout도 B의 프로세스와 화면으로 찾음), A는 페이지, 도구의 전체 출력, 질문 카드가 보여 줄 계획·질문, 그리고 채팅이 화면에 있는 동안 1.5초마다 묻는 짧은 변경 서명만 전달합니다. B는 자기 패인에 대해서만 답하고, B가 다시 붙인 PC의 패인에는 답하지 않으며, 페이지가 이미 보여 주는 것 말고는 기록의 경로나 파일이 연결을 건너가지 않습니다.

마지막으로 고른 화면은 패인마다 기억합니다. 한 번도 고르지 않은 패인은 휴대폰·터치 화면에서는 Chat으로, 데스크톱에서는 Terminal로 엽니다. Claude Code도 Codex도 아닌 패인이나 아직 대화를 읽을 수 없는 패인(세션 미보고, 파일 없음)은 터미널만 보여 주고, Chat 버튼에 이유를 표시합니다. 채팅에서 보내는 메시지도 터미널과 같은 입력창·전송 경로를 씁니다.

채팅은 읽고 답하는 화면이라 특수 키 막대(Esc, 화살표, Ctrl 등)는 Terminal 화면에서만 보이고, 입력창(파일, 글, 보내기)은 두 화면 모두에 남습니다. 채팅에서 보낸 메시지는 바로 "보내는 중" 말풍선으로 보이고, 화면이 맨 아래로 내려가 답을 따라갑니다. 에이전트가 일하는 동안에는 맨 끝에 "Claude is working · 1m 12s"(Codex면 "Codex is working") 줄이 보입니다(동작 줄이기 설정이면 움직이지 않습니다). 채팅 위에서 `Ctrl`/`Cmd`+휠, 트랙패드 핀치, 두 손가락 핀치로 채팅 글자 크기(12~24px)를 바꾸며, 터미널 크기와 따로 기억합니다. 채팅 화면에서는 입력창도 이 크기를 따릅니다. 채팅에서 Terminal 화면으로 넘어가면 터미널이 최신 출력까지 내려갑니다. 복사 버튼은 아이콘이고, 복사되면 잠깐 체크 표시로 바뀝니다.

Chat 화면에서 에이전트가 일하는 동안 입력창에 포커스가 없으면 보내기 버튼이 **Stop**(빨간 네모)으로 바뀝니다. 터미널에서 Esc를 누르는 것과 같아서, 특수 키 막대의 Esc와 똑같은 Esc 하나를 패인에 보내 Claude Code나 Codex의 작업을 멈춥니다. 입력창을 누르면(폰에서는 입력창을 탭하면) 버튼이 다시 보내기가 되므로, 에이전트가 일하는 중에도 초안을 보낼 수 있습니다. 버튼이 무엇을 할지는 누르기 시작할 때 정해지므로, 입력창에서 바로 누른 보내기는 항상 보냅니다. Stop은 작업만 끊고 대화는 그대로이므로 확인을 묻지 않고, 입력창의 초안도 건드리지 않으며, 누른 뒤 잠깐 동안 눌리지 않습니다. 에이전트가 Esc를 한 번 더 받아야 하면 다시 누르세요. 에이전트가 일하는 동안에는 입력창에서 Esc를 눌러도 멈춥니다. 다만 `@` 파일 목록, 찾기, 대화상자가 열려 있거나 입력기가 글자를 조합하는 중이면 Esc는 그쪽이 받습니다. 에이전트가 쉬거나 끝났거나 묻고 있을 때, 그리고 특수 키 막대에 Esc가 있는 Terminal 화면에서는 버튼이 보내기로 남습니다. Connect PC로 붙인 PC의 패인에서도 됩니다.

### 질문 카드

선택한 Claude나 Codex 패인은 herdr가 어떤 상태로 알리든(메뉴가 떠 있어도 blocked로 알리지 않을 때가 있습니다) 서버가 그 화면을 읽어 화면에 뜬 메뉴를 카드로 만듭니다. 일반 출력은, 답변 속 번호 목록이라도 카드가 되지 않습니다. Claude Code의 도구 승인(Yes / Yes, and don't ask again / No), 계획 승인, AskUserQuestion 메뉴(하나 고르기, 여러 개 고르기, 직접 입력), 여러 답을 한 번에 보내기 전 확인, 폴더 신뢰 확인 같은 번호 없는 메뉴를 읽고, Codex의 승인(명령 실행, 편집 적용, 폴더 신뢰. "No, and tell Codex what to do differently"는 Esc로 답함), plan 모드 질문(선택지, 또는 "None of the above"의 메모로 직접 입력), 일하는 동안 대기열에 넣은 질문, "Press enter to continue" 메뉴도 읽습니다. herdr가 패인을 blocked로 알리는 동안에만, 어느 리더도 모르는 화면이 마지막 몇 줄과 기본 키(Enter, Esc, 번호 메뉴의 숫자, y/n)를 담은 대체 카드가 됩니다. Claude의 계획·질문 카드 글은 대화 기록에서 Claude가 기다리는 호출(`ExitPlanMode`의 계획 전체, `AskUserQuestion`의 질문·선택지 전체)에서 가져옵니다. 터미널에서는 긴 계획이 화면 위로 밀려나거나, 좁은 패인에서 선택지가 `…`로 잘리기 때문입니다. 선택지 줄, 보내는 키, 답을 확인하는 기준은 그대로 화면입니다. 기록에서 찾지 못하면 화면의 글을 씁니다. 비밀번호 입력 화면은 카드로 만들지 않습니다. Chat 화면에서는 카드가 입력창 바로 위에 붙고, Terminal 화면 위에는 에이전트가 묻고 있다는 배너가 뜹니다. 배너의 **Answer**는 채팅으로 넘어가고, 채팅이 없는 패인이면 같은 카드를 터미널 위에 띄웁니다. 배너는 그 질문에 한해 닫을 수 있습니다.

선택지를 누르면 카드 id를 보냅니다. 서버는 화면을 다시 읽어 질문이 바뀌었으면 `409 prompt_changed`로 거절하고(카드는 새로 읽습니다), 아니면 커서 이동 키를 보낸 뒤 화면에서 커서가 고른 줄에 온 것을 확인하고서야 Enter를 보냅니다. 카드는 선택한 패인이 Claude나 Codex 패인이거나 blocked인 동안에만 터미널 소켓으로 받습니다. 붙인 PC의 패인도 같은 방식으로 동작합니다.

패인에 비밀번호 프롬프트(`[sudo] password for …:`, `Password:`, passphrase, PIN)가 떠 있을 때 입력창으로 보낸 메시지는 입력 히스토리와 알림 요청 기록에 남기지 않습니다.

### 보조 키와 초안

터미널 아래 두 줄 키 막대를 직접 편집할 수 있습니다. 사이드바 아래 ⚙ 설정 메뉴의 **Edit keys**를 누르면 창이 열리고, 목록에서 키(이름 있는 키, F1~F12, Ctrl·Alt·Shift 고정 버튼)를 추가하거나 삭제하고 순서를 바꿉니다. 순서는 데스크톱에서는 행을 끌어 옮기고, 터치 화면에서는 행마다 있는 위·아래 버튼으로 바꿉니다. **Custom combination**은 기본 키(또는 한 글자)와 고른 수정 키로 `Ctrl`+`R`, `Ctrl`+`Shift`+`Z`, `Ctrl`+`Shift`+`F5` 같은 조합을 추가합니다. 저장한 조합은 항상 그 조합만 보내고, 일반 키는 지금처럼 눌러 둔 Shift·Ctrl·Alt를 함께 보냅니다. PgUp·PgDn은 손가락이나 휠처럼 지난 출력을 한 화면씩 넘깁니다. less·vim처럼 직접 넘기는 프로그램에는 Shift를 먼저 누르고 PgUp·PgDn을 누르면 원래 키가 갑니다. Ctrl·Alt를 함께 누르거나 비춰 보이는 패인에서는 지금처럼 키를 보냅니다. 휴대폰 키보드에서도 Ctrl 같은 고정 버튼을 누른 뒤 친 한 글자는 그 조합키(예: Ctrl+C)로 가고 입력창에 남지 않습니다. 배치는 이 브라우저에 최대 40개까지 저장되고 바로 적용되며, **Reset to default**로 처음 막대로 되돌립니다. 채팅 화면에서는 지금처럼 막대가 숨겨집니다.

패인마다 보내지 않은 입력창 글을 따로 기억합니다. 다른 패인을 열면 쓰던 글을 저장하고 그 패인의 초안을 보여주며, 새로고침해도 초안이 돌아옵니다(패인 30개까지, 패인당 8000자, 일주일 보관, 이 브라우저에 저장). 메시지를 보내면 그 초안은 지워집니다. 비밀번호 답으로 보낸 글은 초안으로 남기지 않습니다.

### 입력

attach된 터미널을 클릭하거나 탭하고 입력하면 문자와 Tab·방향키·Enter·Ctrl 조합을 현재 패인으로 즉시 보내므로 셸이나 에이전트의 자동완성을 그대로 조작할 수 있습니다. 터미널에서 `Ctrl+Enter`는 일반 터미널처럼 줄바꿈 문자(`Ctrl+J`)를 보내므로 Claude Code와 Codex에서 전송하지 않고 새 줄을 엽니다. 터미널 위를 드래그하면 프로그램에 마우스 클릭을 보내지 않고 글자를 선택합니다. 선택하면 **Copy** 버튼이 뜨고, `Ctrl+C`로도 복사합니다. 폰에서는 손가락을 0.5초쯤 누르고 있다가 끌면 선택하며, 짧게 끌면 그대로 스크롤합니다. 아래의 입력창은 작성 후 전송 방식이고, 비춰 보이는 패인에는 이 방법으로만 입력합니다. 폰에서 키보드를 내린 뒤 키 막대를 눌러도 키보드가 다시 올라오지 않습니다. 키보드가 올라오면 화면이 그 위 공간에 맞춰져 입력창과 키 막대가 키보드 바로 위에 붙고, 터미널은 크기를 그대로 둔 채 맨 아래(프롬프트가 있는 곳)를 보여 줍니다. 키보드를 열고 닫아도 패인 크기는 바뀌지 않습니다.

터미널 화면에서 `Ctrl`+`F`(Mac은 `Cmd`+`F`)를 누르거나 패인 머리글의 돋보기를 누르면 **터미널 안 찾기** 막대가 열립니다. 패인의 Herdr 이전 기록 전체를 Herdr의 복사 모드 검색으로 찾고(대문자가 있으면 대소문자를 구분), "3/17"처럼 개수를 보여 주며, 그 패인의 화면을 일치한 곳으로 스크롤합니다. 이 스크롤은 그 패인을 연 모든 클라이언트에 함께 적용됩니다. `Enter`는 더 이전 일치로, `Shift`+`Enter`는 더 최근 일치로 이동하고, 화면에 보이는 일치는 색으로 표시되며, `Esc`로 닫으면 화면은 그 자리에 둡니다. 입력창 등 다른 글 입력란에서는 `Ctrl`+`F`가 브라우저의 찾기로 남고, 비춰 보이는 패인에서는 찾기를 쓸 수 없습니다. 찾기는 Herdr 소켓 API의 복사 모드 검색을 쓰며 Herdr 0.9.3에서 확인했습니다. 이 검색이 없는 이전 Herdr에서는 찾기 막대가 Herdr가 알려 준 이유와 함께 실패했다고 보여 주고, HerdRabbit의 나머지 기능은 그대로 동작합니다.

Chat 화면에서는 같은 단축키와 돋보기가 **채팅 안 찾기**를 엽니다. 페이지에 이미 불러온 메시지(그려진 내용, 펼쳐 둔 작업 블록 포함. 접힌 작업 블록 안은 찾지 않음)를 찾아 일치를 모두 표시하고 "3/17"처럼 개수를 보여 주며, 현재 일치를 화면 가운데로 스크롤합니다(접힌 코드 블록이면 펼침). `Enter`는 위로, `Shift`+`Enter`는 아래로 이동하고 `Esc`로 닫으면 표시가 사라집니다. 아직 불러오지 않은 이전 메시지가 있으면 막대가 알려 주고, 버튼으로 불러올 수 있습니다.

| 동작 | 키 |
| --- | --- |
| 마우스 중심 환경에서 입력 전송 | `Enter` |
| 마우스 중심 환경에서 줄바꿈 | `Ctrl+Enter` |
| 터치 중심 환경에서 줄바꿈 | `Enter` |
| 터치 중심 환경에서 입력 전송 | 오른쪽 화살표 버튼 |
| 터치 기기에 연결한 외장 키보드로 전송 | `Ctrl+Enter` 또는 `Cmd+Enter` |
| 이전에 전송한 입력 불러오기 | `↑` |
| 이후 입력 또는 작성 중이던 초안으로 이동 | `↓` |

선택한 패인이 셸 프롬프트를 받고 있다면 입력한 문자열은 해당 패인의 명령으로 실행됩니다. 제출은 Herdr의 `pane run`으로 텍스트와 Enter를 원자적으로 전달합니다. 서버에는 패인과 무관한 임의 셸 실행 API가 없습니다.

입력창은 기본 한 줄 높이이며 줄바꿈이나 자동 줄바꿈에 맞춰 최대 5줄까지 늘어납니다. 5줄을 넘으면 입력창 내부에서 스크롤합니다.

입력창 맨 앞이나 공백 뒤에 `@`를 치면 Claude Code와 Codex가 받는 방식대로 파일을 가리킬 수 있습니다. 입력창 위 목록에 선택한 패인의 작업 폴더(그 패인에서 도는 프로그램의 폴더, 없으면 패인이 시작한 폴더)의 이름이 폴더 먼저, 최대 50개까지 나옵니다. 더 치면 좁혀지고(`@src/ap`), `↑`/`↓`로 이동, `Enter`나 `Tab`(또는 탭)으로 고르며, `Esc`는 보내지 않고 목록만 닫습니다. 목록이 열려 있는 동안 `Enter`는 절대 전송하지 않습니다. 폴더는 `@src/`로 들어가고 바로 그 안의 이름을 보여 주며, 파일은 뒤에 공백을 붙여 `@src/app.js `로 들어갑니다. 공백이 있는 이름은 Claude Code가 받는 형태인 따옴표로 감싸 `@"my folder/notes.md"`처럼 넣습니다. `@/절대/경로`는 루트부터 찾고, 숨김 이름은 앞의 `.`를 쳤을 때만 보이며, 잠긴 파일은 보여 주지 않습니다. `@~/`는 완성하지 않습니다. 홈 폴더는 패인이 도는 머신의 것이고 목록 API로는 알 수 없으니, 패인 폴더 기준 경로나 절대경로를 쓰세요. 폴더를 모르는 패인이나 목록을 읽지 못한 폴더에서는 그냥 목록이 뜨지 않습니다.

입력창 맨 앞에 `/`를 치면 선택한 패인의 에이전트가 받는 명령을 고를 수 있습니다. Claude Code 패인에서는 Claude Code 자체 명령(`/compact`, `/model` 등), 내 스킬과 명령(`~/.claude/skills/<이름>/SKILL.md`, `~/.claude/commands/**/*.md`, 하위 폴더의 것은 `폴더:이름`), 프로젝트의 것(패인 작업 폴더의 `.claude/skills`, `.claude/commands`. git 저장소 안이면 그 위로 저장소 루트까지의 폴더도 포함), 설치된 플러그인의 것(`~/.claude/plugins/installed_plugins.json` 기준, `플러그인:이름`)을 보여 주고, Codex 패인에서는 Codex 자체 명령과 `~/.codex/prompts`의 프롬프트(`prompts:이름`)를 보여 줍니다. 각 줄에는 이름, 한 줄 설명, 출처(built-in, user, project, plugin)가 나옵니다. 더 치면 목록이 좁혀지고(친 글자로 시작하는 이름이 먼저, 그다음 이름이나 설명에 그 글자가 들어간 것), 키와 탭은 `@` 목록과 같습니다. 고르면 `/이름 `이 뒤에 공백과 함께 들어가고 아무것도 보내지 않습니다. 각 파일에서는 frontmatter의 이름과 설명(없으면 첫 줄)만 읽고 본문은 읽지 않으며, 그 폴더들 밖의 파일은 열지 않습니다. 에이전트 자체 명령은 HerdRabbit에 적어 둔 고정 목록이라, CLI 버전에 따라 실제와 몇 개 다를 수 있습니다. 플러그인은 Claude Code 설정에서 꺼 두었더라도 설치된 대로 보입니다. HerdRabbit은 그 설정 파일을 읽지 않습니다. Connect PC로 붙인 PC의 패인은 그 PC가 이 버전 이상이면 그 PC가 직접 읽은 목록(그 PC의 스킬과 명령, 패인 프로젝트의 것, 플러그인, 프롬프트)을 보여 주고, 그보다 오래된 버전이면 에이전트 자체 명령만 보여 줍니다. 다른 프로그램이 도는 패인에서는 목록이 나오지 않습니다.

입력 정책은 기기 이름이 아니라 브라우저의 터치 정보를 조합해 결정합니다. 기본 포인터 판정뿐 아니라 보조 포인터와 터치 포인트 수도 확인하며, 터치 포인트 기반 fallback은 1024px 이하 화면에서만 사용해 창이 좁은 일반 PC를 터치 기기로 오인하지 않도록 합니다. 브라우저는 외장 키보드 연결 여부를 안정적으로 제공하지 않으므로 자동 전환하지 않으며, 외장 키보드에서는 `Ctrl+Enter` 또는 `Cmd+Enter`로 전송합니다.

### 파일

입력창 옆 첨부 버튼과 사이드바 맨 아래 폴더 아이콘은 모두 **Uploads** 대화상자를 엽니다. 파일을 하나 이상 고르고 **Upload**를 누르면 HerdRabbit이 실행되는 머신의 공용 업로드 폴더에 하나씩 차례로 저장되고, 저장된 절대경로가 고른 순서대로 입력창에 삽입되어 에이전트에게 바로 넘길 수 있습니다. 실패한 파일은 이유와 함께 알려주고 나머지는 계속 올립니다. 직접 전송을 누르기 전까지는 아무것도 보내지 않습니다. 같은 대화상자에서 이미 올린 파일 목록을 보고 경로 삽입·복사, 다운로드, 삭제를 할 수 있습니다.

아무것도 열지 않고 터미널 화면에 파일을 여러 개 한꺼번에 끌어다 놓아도 되고, `Ctrl`/`Cmd`+`V`로 이미지를 붙여넣어도 같은 방식으로 업로드됩니다. 스크린샷을 클립보드에서 입력창의 경로까지 한 번에 옮길 수 있으며, 받은 시각이 담긴 이름으로 저장됩니다. 일반 텍스트 붙여넣기는 그대로입니다.

탐색은 사이드바에서 따로 합니다. 사이드바에는 탭이 두 개 있습니다. **Sessions**는 지금까지의 프로젝트 목록이고, **Files**는 머신 파일시스템의 트리입니다. 폴더는 이름이나 옆의 화살표를 누르면 그 자리에서 펼쳐지고, 폴더 행의 버튼을 누르면 그 폴더가 트리의 뿌리가 되어 깊은 경로에서 들여쓰기를 되돌릴 수 있습니다. 탭 맨 아래 경로 입력칸으로 폴더에 바로 가고 옆의 ↑ 버튼으로 상위 폴더에 가며, 점으로 시작하는 파일도 늘 함께 보입니다. 어느 파일이든 그 행에서 현재 기기로 내려받을 수 있습니다.

탭 맨 아래 경로 입력칸으로 어디든 바로 갈 수 있습니다. 입력하면 이름이 맞는 폴더가 후보로 나오고, 방향키로 옮겨 `Enter`로 엽니다. 탭을 다시 열면 마지막으로 보던 폴더에서 시작하며, 처음 열 때는 업로드 폴더에서 시작합니다.

로그인 키와 HerdRabbit 자체 설정은 열지 않습니다. `~/.ssh`, `~/.gnupg`, `~/.aws`, `~/.azure`, `~/.kube`, `~/.password-store`, `~/.local/share/keyrings`, `~/.config/gh`, `~/.config/gcloud`, `~/.config/rclone`, `~/.netrc`, `~/.git-credentials`, `~/.docker/config.json`, `~/.npmrc`, `~/.pypirc`, `~/.cargo/credentials`, AI CLI 로그인 파일(`~/.claude/.credentials.json`, `~/.claude.json`, `~/.codex/auth.json`, `~/.config/claude*`), HerdRabbit 설정 폴더는 트리에 이름만 **locked**로 보이고 펼치거나 미리 보거나 내려받을 수 없습니다. 심볼릭 링크를 거쳐도, Connect PC로 붙은 PC에서도 같습니다.

탐색은 읽기 전용입니다. 트리에서는 아무것도 바꿀 수 없고, 업로드와 삭제는 Uploads 대화상자에서 합니다. 터미널에서 업로드 폴더로 복사한 파일도 그 대화상자에 나타납니다. 업로드 폴더 위치는 `HERDR_WEB_FILES_DIR`을 지정하지 않으면 `~/.local/share/herdrabbit/files`이며, 자격증명이 저장되는 설정 디렉터리와 의도적으로 분리했습니다. 업로드와 다운로드는 기본적으로 크기 제한이 없고, `HERDR_WEB_MAX_TRANSFER_MB`로 둘 모두에 적용되는 제한(MB)을 하나 둘 수 있습니다. 폴더 자체에는 용량이나 개수 제한이 없어 디스크가 찰 때까지 쌓이고 자동으로 지워지지 않습니다.

머신이 둘 이상 등록되면 Files 탭에 서버 선택이 생깁니다. 고른 머신의 홈에서 트리가 시작되고, 머신마다 마지막으로 보던 폴더를 따로 기억합니다.

그 선택이 업로드가 가는 곳이기도 합니다. 고르기 전에는 보고 있는 세션을 따라가고 경로가 입력창에 삽입됩니다. 머신을 고르면 탐색과 업로드 양쪽에 고정되며 새로고침해도 유지됩니다. 고정한 머신이 지금 세션이 도는 머신과 다르면 경로를 **삽입하지 않습니다** — 그 세션이 열 수 없는 파일을 가리키게 되니까요 — 대신 어디에 올라갔는지 알려줍니다. 첨부 버튼과 업로드 다이얼로그는 어느 쪽이든 대상 머신을 표시합니다.

붙인 PC의 파일은 그 PC가 직접 읽고 씁니다. 봉쇄 조건은 모든 머신에서 같습니다 — 탐색은 읽기 전용이고, 쓰기는 그 머신 자신의 업로드 폴더에만 닿습니다.

iOS에서 PWA를 독립 실행 모드로 쓰면 내려받은 파일이 저장되지 않고 열릴 수 있습니다. 이때는 공유 시트로 저장하세요.

에이전트가 출력에 적은 파일 이름은 그 파일로 가는 링크가 됩니다. "wrote `src/api.mjs`", "see `./docs/plan.md`" 같은 경로를 누르면 뷰어가 열리고, 상대경로는 그 패인의 디렉터리를 기준으로 풀립니다. 뷰어가 보여줄 수 없는 파일(예: `app-release.aab`)은 Files 탭이 그 폴더로 열리며 그 파일이 선택되고, 파일이 이미 없으면 그렇다고 알려 줍니다. 끝까지 적힌 폴더 경로도 링크입니다. 절대경로(`/home/me/proj`)나 `./`, `../`로 시작하는 경로를 누르면 Files 탭이 그 폴더 안을 열고, 마지막 이름이 그 폴더에서 파일로 확인되면 부모 폴더에서 그 파일이 선택됩니다. 끝의 슬래시(`/home/me/proj/`)는 폴더라는 뜻입니다. 그 밖의 경로는 마지막 이름이 뷰어가 보여줄 수 있는 파일이거나 글자가 하나 이상 든 확장자가 있는 파일(`name.ext`)일 때만 링크가 되므로 `src/foo`, `node_modules/`, `feat/settings-menu`, `1/2`, `.env`, `v1.2`, `10.0.0.1`은 그대로 글자입니다. 이름 하나뿐인 `/word`(`/compact` 같은 슬래시 명령), `//host/share`, 웹 주소 안의 경로는 폴더 링크가 아닙니다. `~`는 건드리지 않습니다 — 그 홈은 패인이 도는 머신의 것이라 추측할 수 없습니다. 실시간 터미널에서는 이런 경로와 웹 주소에 늘 밑줄이 그어져 폰에서도 보고 누를 수 있고, 출력이 다음 줄로 넘긴 주소도 하나의 링크입니다. 공백이 든 경로는 따옴표로 감싸고 `/`, `./`, `../`로 시작하면 통째로 하나의 링크가 됩니다 — `"/home/me/my folder"`, `'./build output/app.aab'`. 링크는 따옴표 안쪽만이고, 터미널에서도 백틱을 따옴표로 보며, 따옴표가 없으면 경로는 첫 공백에서 끝납니다. 상대경로는 그 패인의 디렉터리를 알 때만 링크가 됩니다. 한글 같은 다른 글자로 된 이름(`/home/me/프로젝트`)도 경로이고, 파일 이름 바로 뒤에 붙은 조사(`src/a.md를`)는 경로에 넣지 않습니다. 채팅 화면은 터미널과 같은 코드로 경로를 찾으므로 같은 글에서 같은 경로가 링크됩니다. 다른 점은 코드 스팬 하나입니다. 코드 스팬은 통째로 하나의 경로로 보므로 이름만 적힌 파일(`app.js`)도 링크가 되고, 공백이 든 경로(`` `/home/me/my folder` ``)도 백틱이 따옴표 노릇을 해 링크가 됩니다. 다음 줄로 넘어간 경로를 잇는 것은 터미널에만 있습니다 — 채팅 글은 화면 폭에서 잘리지 않습니다.

파일은 내려받는 대신 열어볼 수 있습니다. 이미지·동영상·오디오는 그 자리에서 재생되고, 마크다운과 HTML은 그려지며, 텍스트·코드·로그·설정은 글자로 보여줍니다. 폰에서 로그 두 줄 보자고 먼저 저장할 이유는 없습니다.

무엇을 무엇으로 보여줄지는 바이트를 훑어서가 아니라 이름을 허용목록에 맞춰 정합니다. 아무것도 실행되지 않되, 실행될 수 있는 두 형식은 거절하는 대신 보여주는 방식으로 다룹니다. SVG는 스크립트를 실행하지 않는 `<img>`에 넣습니다. HTML은 자기 정책이 `sandbox`로 끝나는 응답으로 프레이밍합니다 — 불투명한 출처에 스크립트 없음이며, 우리 프레임만이 아니라 그 URL을 여는 누구에게나 그렇습니다. 그 위에서라야 저장된 보고서가 자기 스타일시트를 그대로 씁니다. 둘 다 집으로 전화를 거는 파일로 실측했고 아무것도 빠져나가지 못했습니다. 마크다운도 같은 길입니다. 서버가 `marked`로 그려서 보내므로 같은 프레임에 같은 정책으로 들어가고 브라우저는 아무것도 더 받지 않습니다. 어떤 주소가 링크가 되는지, 문서에 박힌 마크업을 어떻게 할지는 파서가 아니라 여기서 정합니다 — http(s)가 아니면 글자로 남고, 박힌 마크업은 자기를 이루는 글자로 보입니다. 어느 쪽이든 버튼 한 번으로 소스로 볼 수 있습니다. PDF는 다이얼로그가 아니라 새 탭에서 열립니다. 브라우저마다 갈리는 건 프레임 안의 PDF입니다 — Android Chrome은 프레임에 아무것도 안 그리고 iOS Safari는 첫 장만 그립니다. 탭은 프레이밍이 아니라서 어디서나 되고, 페이지 모양으로 쓰인 문서에 제 높이를 줍니다. 덕분에 PDF는 프레이밍 규칙에 예외가 필요 없고 받지도 않습니다 — 열리는 건 HTML 하나뿐이고, 이미지 응답은 여전히 `frame-ancestors 'none'`입니다. 텍스트도 같은 방식입니다 — 불투명한 바이트로 받아 글자로 써넣고, 타입을 협상하지 않습니다. 다운로드는 그대로입니다. 여전히 `application/octet-stream` 첨부이고, 그것이 저장된 페이지가 이 출처에서 실행되지 못하게 막는 장치입니다.

동영상은 탐색됩니다. 보기 링크가 바이트 범위에 답하고, 붙인 PC의 파일도 마찬가지입니다 — 파일을 가진 머신이 조각을 내주기 때문입니다.

### AI 계정

구독형 CLI는 세션 리밋이나 주간 리밋에 걸리면 멈추고, 다른 계정으로 옮기려면 보통 다시 로그인해야 합니다. 서버 행 메뉴의 **AI accounts**는 계정마다 로그인을 그 머신에 보관해 두어 전환을 한 번에 끝냅니다. Claude Code와 Codex를 지원합니다.

대화상자는 CLI마다 이메일을 A부터 Z 순서로 보여 주고, 지금 쓰는 계정은 그 자리에서 표시가 붙습니다. 열 때 지금 로그인된 계정을 저장하므로 따로 저장할 필요가 없습니다. 계정 아래 줄은 일주일 안에 다시 로그인해야 하거나 이미 만료됐을 때만 나옵니다. Claude Code 로그인은 대략 한 달 가고, Codex는 끝나는 날짜를 기록하지 않습니다. 계정에 관해 그 밖의 정보는 보여주지 않습니다.

- 목록 끝의 **Add account**는 `AI login: …` 프로젝트를 열고 그곳에 로그인 명령을 입력합니다. `claude auth login` 또는 `codex login --device-auth`이며, 각자 비어 있는 전용 디렉터리를 가리킵니다. 지금 쓰는 계정이 있는 곳에서 로그인하면 그 계정의 토큰이 폐기되기 때문에 따로 떨어진 곳에서 로그인합니다. Codex의 device code 로그인은 ChatGPT 보안 설정에서 먼저 켜야 합니다. 로그인 완료는 알아서 알아챕니다. 화면이 몇 초마다 CLI가 그 디렉터리에 로그인 정보를 썼는지 확인하고, 쓰는 순간 계정을 저장한 뒤 프로젝트를 닫습니다. 그리고 AI accounts 창이 다시 열려 새 계정을 **Just added**로 표시합니다. 다른 창이 열려 있으면 끼어들지 않습니다. 새로고침해도 기다리던 로그인을 잃지 않습니다. 머신이 아직 열려 있는 로그인을 기억하고, 화면이 새로 뜨거나 AI accounts를 열 때 다시 이어서 확인합니다. 20분이 지나면 확인을 멈추고, 그 전에 끝내려면 AI accounts의 **Cancel sign-in**을 누르면 됩니다. 그 프로젝트에 입력한 내용은 입력 기록에 남지 않습니다.
- 계정 줄 ⋯ 메뉴의 **Switch**는 머신 전체의 계정을 바꿉니다. 설정, MCP 서버, 대화 기록, 메모리는 그대로라서 `claude --continue`나 `codex resume`으로 다른 계정이 멈춘 곳부터 이어갈 수 있습니다. 바뀌기 전 계정은 먼저 저장하므로, 쓰는 동안 CLI가 갱신한 토큰도 보존됩니다. Herdr가 어느 패인에서든 그 CLI가 실행 중이라고 알려주면 해당 패인 목록을 보여주고 확인을 받습니다. 그 패인들은 재시작하기 전까지 이전 계정을 씁니다. Herdr 밖에서 실행한 CLI는 감지하지 못합니다.
- 같은 메뉴의 **Remove**는 저장된 사본을 지웁니다. 어디에서도 계정을 로그아웃시키지는 않습니다.

계정은 머신마다 따로 보관합니다. 붙인 PC에서는 저장·로그인·전환을 그 PC에서 실행하고 어느 계정이 어디에 있는지만 돌아옵니다. 로그인 정보는 머신 사이를 오가지 않습니다.

저장한 로그인은 `~/.config/herdr-bridge/ai-accounts`(또는 `HERDR_WEB_AI_ACCOUNTS_DIR`로 지정한 디렉터리)에 둡니다. 해당 OS 사용자만 읽을 수 있는 `0700` 디렉터리 안의 `0600` 파일입니다.

전환되는 것은 CLI 자신의 파일입니다. `~/.claude/.credentials.json`과 `~/.claude.json`의 `oauthAccount` 필드, 그리고 `~/.codex/auth.json`입니다. HerdRabbit 서비스 환경에 `CLAUDE_CONFIG_DIR`이나 `CODEX_HOME`이 있으면 그 디렉터리를 씁니다. 로그인을 keyring에 저장하도록 설정한 Codex는 전환할 수 없다고 표시하고, 환경에 `ANTHROPIC_API_KEY`나 `CLAUDE_CODE_OAUTH_TOKEN`이 있으면 저장된 계정보다 그것이 우선합니다. macOS의 Claude는 로그인을 키체인에 두므로 지원하지 않습니다.

### 출력과 이전 기록

터미널의 출력과 이전 기록은 Herdr의 화면 및 스크롤백에서만 가져오며 Claude JSONL 기록과 Codex rollout을 터미널에 섞지 않습니다. 그 기록은 Chat 화면이 따로 읽습니다(Claude 계획·질문 카드의 글도 거기서 가져옵니다). attach된 터미널에서는 휠이나 손가락으로 Herdr의 이전 기록을 스크롤하고, 비춰 보이는 패인은 현재 화면만 보여 줍니다. 설치·업데이트 시 Claude 전역 설정에 `tui: "default"`와 `env.CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN: "1"`을 적용하고 기존 설정은 백업합니다. 실행 중인 Claude는 재시작 후 적용됩니다. HerdRabbit을 돌리는 머신마다 자기 설치·업데이트에서 적용됩니다.

현재 터미널의 입력·대화 전송·기능키와 화면 갱신은 `/api/terminal` WebSocket을 사용합니다. attach된 패인은 Herdr의 출력을 그대로 받고, 비춰 보이는 패인은 최초 화면 이후 변경된 부분만 받습니다. Herdr는 terminal attach 밖에서는 범용 화면 변경 구독을 제공하지 않아 서버가 변경을 감지합니다. 입력 직후·출력 변경 중에는 조회 완료 후 50ms, 조용할 때는 500ms 간격으로 확인하며 같은 패인·조회 범위의 구독은 공유합니다. 브라우저가 백그라운드로 가면 연결을 닫고 복귀 시 새 화면을 받습니다. 세션 상태는 Herdr의 `pane.agent_status_changed` 이벤트를 WebSocket으로 전달해 선택하지 않은 세션까지 갱신합니다. 프로젝트·세션 목록은 2초마다 HTTP로 조회하며, 상태 구독 연결 후에도 HTTP로 다시 동기화합니다. 상태 구독이 끊기면 HTTP 목록 조회로 보완하고 재구독합니다. 로그인·프로젝트·세션 관리는 HTTP를 유지합니다. 푸시 알림 동작은 유지합니다.

### 화면 설정

사이드바 하단 버튼으로 라이트·다크 모드를 전환합니다. 터미널 영역 위에서 `Ctrl+휠`을 사용하거나 트랙패드를 확대·축소하면 터미널 글자 크기가 바뀝니다. 모바일에서는 터미널 위에서 두 손가락을 모으거나 벌려 글자 크기를 조절합니다. 한 손가락 스크롤은 그대로 동작합니다. 글자 크기는 터미널 출력과 입력창에 함께 적용되며 브라우저 `localStorage`에 저장됩니다.

## 환경 변수

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `HERDR_WEB_HOST` | `127.0.0.1` | 바인딩할 주소. `127.0.0.1`, `0.0.0.0`, 또는 Tailscale 주소처럼 특정 인터페이스 하나. 주소 하나로 묶는 것이 가장 좁습니다 — 그 머신이 물려 있는 다른 모든 네트워크에서 서비스가 아예 보이지 않고, 그 주소는 요청 host로도 자동 허용됩니다. 이름은 listen 시점에 해석되므로 거부합니다. |
| `HERDR_WEB_PORT` | `38787` | 1024–65535 범위의 수신 포트 |
| `HERDR_WEB_ALLOWED_HOSTS` | 비어 있음 | 역방향 프록시와 Tailscale용 추가 Host 이름. 쉼표로 구분 |
| `HERDR_WEB_PEER_HOST`, `HERDR_WEB_PEER_PORT`, `HERDR_WEB_PEER_ADDRESSES`, `HERDR_WEB_PEER_LOGINS`, `HERDR_WEB_HUB` | 설정 안 함, 포트는 1024–65535 정수, 기본 `38788` | Connect PC 포트와 붙을 수 있는 PC. [HerdRabbit이 도는 다른 PC](#herdrabbit이-도는-다른-pc-connect-pc) 참고. `HERDR_WEB_PEER_HOST`를 설정해야 열리고, 허용 목록이 둘 다 비어 있으면 아무도 받지 않습니다. |
| `HERDR_WEB_SERVERS_FILE` | `~/.config/herdr-bridge/servers.json` | Connect PC로 붙인 PC 목록 |
| `HERDR_WEB_MAX_TRANSFER_MB` | 설정 안 함(제한 없음) | 업로드·다운로드 1건의 최대 크기(MB, 양의 정수). 설정하지 않으면 제한 없음. 여럿이 쓰거나 디스크가 넉넉하지 않은 호스트에서는 제한을 두는 것을 권장합니다 |
| `HERDR_WEB_AUTH_FILE` | `~/.config/herdr-bridge/auth.json` | 비밀번호 해시와 세션 서명 키를 저장한 인증 파일 |
| `HERDR_WEB_PUSH_FILE` | `~/.config/herdr-bridge/push.json` | VAPID 키와 브라우저 Push 구독을 저장한 파일 |
| `HERDR_WEB_AI_ACCOUNTS_DIR` | `~/.config/herdr-bridge/ai-accounts` | 저장한 Claude Code·Codex 로그인 |
| `HERDR_BIN` | `herdr` | 사용할 Herdr 실행 파일 경로 |

예시:

```bash
HERDR_WEB_HOST=0.0.0.0 \
HERDR_WEB_PORT=38787 \
HERDR_WEB_ALLOWED_HOSTS=my-server.example-tailnet.ts.net \
HERDR_BIN="$HOME/.local/bin/herdr" \
npm start
```

`127.0.0.1`은 이 머신과 Tailscale Serve를 통한 접속만 허용하는 권장값입니다. `0.0.0.0`은 LAN에서도 직접 접속할 때만 사용하세요. 비밀번호를 설정했더라도 Herdr 패인 입력 권한이 제공되므로 공인 인터넷에 직접 노출하면 안 됩니다.

## systemd 사용자 서비스

권장 설치 방법은 저장소 경로, Node.js와 Herdr 실행 파일, Tailscale DNS 이름, 사용 가능한 포트를 자동으로 반영하는 설치 스크립트입니다.

```bash
npm run install-service
```

새 설치는 `38787`을 먼저 확인하고, 사용 중이면 `30000`부터 빈 포트를 찾습니다. 다른 Linux 계정의 서비스나 기존 Tailscale HTTPS가 사용하는 포트도 제외합니다. 기존 사용자 서비스를 다시 설치할 때는 현재 배정된 `30000–39999` 포트를 그대로 사용합니다.

저장소의 [`systemd/herdrabbit.service`](systemd/herdrabbit.service)는 수동 설치용 예시입니다. 다른 머신에서는 다음 항목을 실제 경로와 호스트명으로 수정해야 합니다.

- `Documentation`
- `WorkingDirectory`
- `HERDR_WEB_HOST`
- `HERDR_WEB_ALLOWED_HOSTS`
- `HERDR_WEB_AUTH_FILE`
- `HERDR_BIN`
- `ExecStart`의 Node.js와 저장소 경로

실제 경로를 확인합니다.

```bash
command -v node
command -v herdr
pwd
```

수동으로 서비스 파일을 설치하고 편집하려면 다음을 실행합니다.

```bash
mkdir -p ~/.config/systemd/user
cp systemd/herdrabbit.service ~/.config/systemd/user/
systemctl --user edit --full herdrabbit.service
systemctl --user daemon-reload
systemctl --user enable --now herdrabbit.service
```

상태와 로그를 확인합니다.

```bash
systemctl --user status herdrabbit.service
journalctl --user -u herdrabbit.service -f
```

로그아웃 후에도 사용자 서비스를 계속 실행해야 한다면 배포 환경 정책을 확인한 뒤 linger를 활성화할 수 있습니다.

```bash
sudo loginctl enable-linger "$USER"
```

## Tailscale Serve로 HTTPS 제공

[Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve)는 tailnet 안의 요청을 로컬 서비스로 프록시합니다. Serve 주소는 공인 인터넷 주소가 아니며, 접속하는 서버와 클라이언트 모두 같은 tailnet에 연결되어 있어야 합니다.

`npm run install-service`는 아래 과정을 자동으로 수행합니다. 이 절은 수동 설정이나 문제 해결이 필요할 때 사용합니다.

### 1. Tailscale 연결 확인

서버와 접속할 휴대폰·PC에서 Tailscale에 로그인한 뒤 서버에서 확인합니다.

```bash
tailscale status
```

노드의 전체 DNS 이름은 다음처럼 확인할 수 있습니다. `jq`가 없다면 `tailscale status --json` 출력의 `Self.DNSName` 값을 확인하세요.

```bash
tailscale status --json | jq -r '.Self.DNSName | rtrimstr(".")'
```

예시는 `my-server.example-tailnet.ts.net` 형태입니다.

### 2. Tailscale Host 허용

HerdRabbit 서비스의 `HERDR_WEB_ALLOWED_HOSTS`에 위 DNS 이름을 포트나 `https://` 없이 넣습니다.

```ini
Environment=HERDR_WEB_ALLOWED_HOSTS=my-server.example-tailnet.ts.net
```

설정을 바꿨다면 다시 로드합니다.

```bash
systemctl --user daemon-reload
systemctl --user restart herdrabbit.service
```

Host가 허용되지 않으면 브라우저에서 `421 Request host rejected`가 반환됩니다.

### 3. HTTPS Serve 활성화

HerdRabbit이 선택된 포트에서 실행 중인 상태에서 로컬 포트와 같은 HTTPS 포트를 등록합니다. 예를 들어 포트가 `38787`이면 다음과 같습니다.

```bash
sudo tailscale serve --bg --yes --https=38787 http://127.0.0.1:38787
```

HTTPS가 tailnet에서 처음 사용되는 경우 Tailscale이 MagicDNS와 HTTPS 인증서 사용 동의를 요청할 수 있습니다. 자세한 동작은 [Serve CLI 문서](https://tailscale.com/docs/reference/tailscale-cli/serve)와 [HTTPS 인증서 문서](https://tailscale.com/docs/how-to/set-up-https-certificates)를 참고하세요.

설정 결과와 접속 URL을 확인합니다.

```bash
tailscale serve status
```

출력 예시:

```text
https://my-server.example-tailnet.ts.net:38787 (tailnet only)
|-- / proxy http://127.0.0.1:38787
```

`--bg` 설정은 Tailscale 재시작이나 머신 재부팅 후에도 유지됩니다. Serve 설정을 모두 제거하려면 다음을 실행합니다.

```bash
sudo tailscale serve reset
```

Tailscale을 연결하지 않은 기기에서는 이 HTTPS 주소에 접속할 수 없습니다. 비밀번호 유무와 관계없이 공개 인터넷 노출 기능인 Tailscale Funnel에는 연결하지 않는 것을 권장합니다.

## 업데이트

```bash
cd ~/.local/share/herd-rabbit  # 실제 설치 경로
sh ./update.sh
```

서비스를 설치한 Linux 계정으로 실행하세요. 스크립트 자신의 경로(또는 `HERD_RABBIT_INSTALL_DIR`)에서 공식 origin과 수정 없는 `main` 브랜치인지 확인한 뒤 최신 `main`을 받은 뒤 서비스가 쓰는 Herdr를 먼저 업데이트하고(`herdr update --handoff`, 실행 중인 패인 유지), 그다음 코드 반영·의존성 설치·검증·해당 경로의 사용자 서비스 재시작을 수행합니다. Herdr는 파일을 바꾸기 전에 받아 올 코드가 요구하는 최소 버전과 비교합니다. Herdr 업데이트가 실패해도 설치된 Herdr가 충분히 새 버전이면 계속하고, 아니면 아무것도 바꾸지 않고 중단합니다. 중복 실행 잠금이 있으며, 로컬 수정·분기된 커밋이면 아무것도 바꾸기 전에 중단합니다. `main`을 옮긴 뒤 의존성 설치·검증·재시작 중 하나라도 실패하면 이전 커밋으로 되돌리고 그 의존성을 다시 설치하며, 이미 재시작했다면 이전 버전으로 다시 시작합니다. Herdr 자체는 되돌리지 않습니다. Claude 터미널 스크롤백 설정은 검증 뒤에 실행하며 되돌리지 않습니다. 실패하면 재시작 전에 멈추고, 다음 재시작 때 검증된 새 코드가 실행됩니다. 포트·인증·Tailscale 설정과 붙인 PC는 유지합니다. 이전 설치에 `update.sh`가 없다면 처음 한 번 `git pull --ff-only`로 받아오세요. 1.2.10보다 오래된 설치는 디스크에 있던 예전 `update.sh`가 실행되므로 Herdr를 올리지 않습니다. 그 첫 업데이트 전에 Herdr 밖의 터미널에서 `herdr update --handoff`를 실행하세요. Herdr가 0.9.0보다 낮은 동안에는 서버 시작 로그와 머신 Details에 경고가 나옵니다.

서비스 워커가 새 앱 셸을 감지하면 페이지를 한 번 다시 로드합니다. 장시간 열려 있던 탭은 직접 새로고침하는 것이 좋습니다.

### 앱에서 업데이트

페이지는 열 때마다, 그리고 **⚙ → Update**에서 **Check**를 누를 때 새 버전을 확인합니다(주기적으로 확인하지 않습니다). 서비스가 쓰는 checkout에서 origin의 `main`을 받아 지금 실행 중인 것과 비교합니다. 새 버전이 있으면 ⚙ 버튼에 점이 찍히고, Update 창에 실행 중인 버전과 최신 버전, 그 사이의 커밋 제목, 그리고 `update.sh`가 멈출 경우 그 이유가 나옵니다: systemd 사용자 서비스로 실행 중이 아님, origin이 ultivis-iot/HerdRabbit이 아님, `main`이 아님, 로컬 수정, 갈라진 로컬 `main`, 이미 실행 중인 업데이트. **Update**는 먼저 확인을 받은 뒤 같은 `update.sh`를 `systemd-run --user`로 서비스 밖의 별도 유닛에서 실행하므로, 마지막의 서비스 재시작이 업데이트를 멈추지 않습니다. 페이지는 로그를 따라가고 재시작을 기다렸다가 새 버전으로 다시 로드합니다. 실패하면 그렇다고 알리고 로그를 남깁니다(`update.sh`가 스스로 되돌립니다). 로그와 결과는 `~/.local/share/herdrabbit/update/`에 남습니다. Update 창은 Connect PC로 붙인 PC도 각각의 버전·변경·이유와 함께 보여주고, 거기서 **Update**를 누르면 그 PC의 `update.sh`가 실행됩니다. 이 페이지는 어느 PC인지만 보냅니다. 이 기능 이전 버전의 PC에는 "Update it there (older version)"이 나옵니다. 업데이트 시작에는 이 페이지의 로그인 세션이 필요하고, PC마다 1분에 한 번만 시작할 수 있습니다.

npm run dev

테스트는 가짜 Herdr 실행 파일과 임시 상태를 사용하므로 실제 Herdr 패인에 입력하거나 프로젝트·세션을 생성 또는 종료하지 않습니다.

## 문제 해결

### `421 Request host rejected`

접속 중인 DNS 이름을 `HERDR_WEB_ALLOWED_HOSTS`에 추가한 뒤 서비스를 다시 시작합니다. 값에는 프로토콜과 포트를 넣지 않습니다.

### 이 머신 줄의 아이콘이 빨간색으로 표시됨

사이드바에서 이 머신 줄의 머신 아이콘은 이 화면이 HerdRabbit에 닿지 못할 때 빨간색이 되고, 마우스를 올리면 이유가 나옵니다. 모든 머신 줄에는 작은 점도 있어, HerdRabbit이 그 머신에 닿으면 초록, 닿지 않으면 회색입니다. 이 머신 줄에는 Host라고 적힙니다.

```bash
systemctl --user status herdrabbit.service
herdr status server
herdr api snapshot
journalctl --user -u herdrabbit.service -n 100 --no-pager
```

### `Herdr returned invalid JSON`

HerdRabbit이 `api snapshot`, `workspace rename`처럼 JSON을 반환해야 하는 Herdr 명령에서 JSON이 아닌 출력을 받은 경우입니다. `HERDR_BIN`이 올바른 실행 파일인지 확인하고 `herdr api snapshot`을 직접 실행해 JSON 응답 여부를 확인하세요.

### Tailscale HTTPS가 열리지 않음

```bash
tailscale status
tailscale serve status
systemctl --user status herdrabbit.service
```

서버와 클라이언트가 같은 tailnet인지, MagicDNS와 HTTPS 인증서가 활성화됐는지, ACL이 해당 기기의 접근을 허용하는지 확인합니다. [Tailscale Serve 문서](https://tailscale.com/docs/features/tailscale-serve)도 참고하세요.

### 비밀번호를 잊어버림

해당 Linux 계정으로 SSH 접속해 `npm run password`를 실행합니다. 기존 비밀번호는 필요하지 않습니다. 새 비밀번호를 입력하거나 빈 값으로 인증을 해제하면 서비스가 재시작되고 기존 로그인 세션과 Passkey가 무효화됩니다.

### 설치 스크립트가 포트를 찾지 못함

설치 스크립트는 `30000–39999` 전체가 로컬 서비스 또는 Tailscale Serve에서 사용 중일 때 중단됩니다. 사용 상태를 확인합니다.

```bash
ss -ltn
tailscale serve status
```

### 이전 UI나 아이콘이 계속 보임

브라우저 탭이나 설치된 PWA를 완전히 종료한 뒤 다시 실행합니다. 그래도 유지되면 사이트 데이터를 지우거나 PWA를 제거 후 재설치합니다. 사이트 데이터를 지우면 마지막 선택 세션, 접힌 프로젝트, 테마 설정도 초기화됩니다.

## 보안 경계

- 기본 바인딩은 `127.0.0.1`입니다.
- HerdRabbit 로그인 비밀번호는 `scrypt` 해시로만 저장하며 인증 설정 파일은 해당 OS 사용자만 읽을 수 있습니다. 붙인 PC는 자격증명을 갖지 않습니다. PC는 요청이 들어온 tailnet 주소로 서로를 알아봅니다.
- Passkey 개인키와 생체 정보는 HerdRabbit으로 전달되지 않고 공개 credential 정보만 저장합니다.
- 로그인 쿠키에는 `HttpOnly`, `SameSite=Strict`를 적용하고 HTTPS에서는 `Secure`도 적용합니다.
- 비밀번호 변경과 해제 시 서비스를 재시작해 기존 세션과 등록된 Passkey를 무효화합니다.
- 브라우저에서 Passkey를 추가하거나 삭제할 때는 비밀번호를 다시 확인해, 탈취한 세션만으로는 세션보다 오래 남는 로그인 수단을 심을 수 없습니다. 삭제하면 다른 모든 세션이 끝납니다.
- 비밀번호를 5번 틀리면 비밀번호 확인이 1초 잠기고, 더 틀릴 때마다 잠금이 두 배로 늘어 최대 15분까지 갑니다. 로그인과 재확인은 따로 세므로, 로그인 화면에서 누가 비밀번호를 대입해도 로그인된 주인이 분실 기기의 Passkey를 지우는 일은 막히지 않습니다. 맞는 비밀번호를 넣으면 초기화되고, 잠긴 동안에도 Passkey 로그인은 됩니다. 비밀번호는 한 번에 하나만 확인하며, 확인 중에 들어온 다른 시도는 거절합니다.
- 모든 Herdr 호출은 셸을 거치지 않는 `execFile` 인자 배열을 사용합니다.
- Herdr 세션 ID, 프로젝트 ID, 탭 ID, 패인 ID, 이름, 텍스트 길이, 출력 행 수 및 명령 실행 시간을 제한합니다.
- 브라우저가 조합한 임의의 Herdr 세션은 실행하지 않으며, 최근 조회에서 확인된 실행 중 세션만 명령 대상으로 허용합니다.
- 세션과 프로젝트 종료 API는 명시적인 확인 값도 요구합니다.
- 쓰기 API는 서버 시작 시 생성된 CSRF 토큰과 동일 출처 검사를 모두 요구합니다.
- 요청 `Host`는 로컬 인터페이스, 머신 이름 및 명시한 추가 호스트만 허용합니다.
- CORS 허용 헤더를 제공하지 않습니다.
- 엄격한 Content Security Policy, 프레임 차단 및 MIME 스니핑 차단 헤더를 사용합니다.
- 서비스 워커는 정적 앱 셸만 캐시하고 `/api/` 응답과 터미널 출력은 저장하지 않습니다.
- 쓰기는 이 머신의 업로드 폴더에만 닿습니다. 비밀번호 해시와 VAPID 키가 있는 설정 디렉터리 바깥에 둡니다. 업로드와 삭제는 그 폴더 밖의 경로를 지정할 수 없습니다. URL로 들어온 이름은 교정하지 않고 거부하며, 대상은 경로를 조합하지 않고 디렉터리 목록에서 가져옵니다.
- 탐색은 읽기 전용이며 이 머신에서 서비스 계정이 읽을 수 있는 경로에 닿지만, **로그인 키와 HerdRabbit 자체 설정은 목록 안으로 들어가지도, 열지도, 미리 보거나 내려받지도 않습니다**: `~/.ssh`, `~/.gnupg`, `~/.aws`, `~/.azure`, `~/.kube`, `~/.password-store`, `~/.local/share/keyrings`, `~/.config/gh`, `~/.config/gcloud`, `~/.config/rclone`, `~/.netrc`, `~/.git-credentials`, `~/.docker/config.json`, `~/.npmrc`, `~/.pypirc`, `~/.cargo/credentials`, AI CLI 로그인 파일(`~/.claude/.credentials.json`, `~/.claude.json`과 그 백업, `~/.codex/auth.json`, `~/.config/claude*`, `CLAUDE_CONFIG_DIR`/`CODEX_HOME`이 가리키는 곳), HerdRabbit 데이터(`~/.config/herdr-bridge/`, 그리고 환경 변수로 옮긴 비밀번호·푸시·서버 목록·저장된 로그인 경로). 경로는 심볼릭 링크를 풀어서 비교하므로 키를 가리키는 링크도 키와 똑같이 거부됩니다. 목록에서는 이름과 종류만 locked로 보입니다. 같은 목록이 Connect PC로 붙은 PC의 파일(그 PC 기준)에도 적용되고, 업로드 폴더가 그 안에 있으면 서비스가 시작하지 않습니다. 이 목록 밖은 OS 파일 권한이 경계이며 `/proc/self/environ` 같은 것은 여전히 읽힙니다. 인증된 클라이언트는 이미 터미널 패인으로 그 계정의 임의 명령을 실행할 수 있으므로 권한 상승은 아닙니다 — 이 목록은 로그인 정보가 파일 브라우저로 머신 밖에 나가는 길을 막는 것이지 터미널을 막는 것은 아닙니다. HerdRabbit을 root나 공용 계정으로 실행하지 말아야 할 이유가 하나 더 늘어납니다.
- 어떤 머신도 다른 머신의 자격증명을 쥐지 않습니다. 각자 자기 HerdRabbit과 자기 Herdr를 돌리므로, 하나가 뚫려도 나머지가 함께 넘어가지 않습니다.
- **Connect PC 포트**는 화면과 따로 듣는 별도 리스너입니다. `/api/link/`만 응답하고 화면·로그인·브라우저 API는 내주지 않으며, 화면 쪽에는 `/api/link/` 경로가 아예 없습니다. 그래서 붙은 PC가 화면 세션을 쓸 수 없고, 브라우저 세션으로 Connect PC API에 들어올 수도 없습니다. PC는 소켓의 주소로(그리고 `HERDR_WEB_PEER_LOGINS`가 있으면 그 주소를 `tailscale whois`로 확인한 계정으로) 들어오며, 쿠키·비밀번호·헤더로는 들어올 수 없습니다. 허용 목록이 비어 있으면 아무도 들어오지 못합니다.
- Connect PC 포트는 자기 주소로 온 요청에만 답합니다. `Host`가 듣고 있는 주소와 포트(IPv6는 `[주소]:포트`)나 이 PC의 tailnet DNS 이름과 정확히 같지 않으면 `421`, 브라우저가 붙이는 헤더(`Origin`, `Sec-Fetch-Site`, `Sec-Fetch-Dest`)가 있으면 `403`입니다. 그래서 다른 이름의 웹 페이지가 이 주소로 풀리게 해도(DNS rebinding), 허용한 PC의 브라우저에서 그 페이지가 이 포트를 쓸 수 없습니다. 연결은 최대 64개, 상태 스트림은 최대 16개이고, 요청은 헤더를 5초 안에, 전체를 3분 안에 보내야 합니다.
- Connect PC로 하는 터미널 attach는 이 포트의 유일한 WebSocket(`/api/link/panes/<pane>/attach`)이며, 업그레이드는 패인을 조회하기도 전에 모든 요청과 똑같은 검사를 거칩니다. 정확한 `Host`, 브라우저 헤더 없음, `/api/link/`만, 허용한 주소나 계정. 거부는 평범한 HTTP 응답이고 아무것도 시작하지 않습니다. 동시에 열 수 있는 attach는 최대 16개, 패인 크기는 1..1000, 허브가 보내는 프레임은 최대 256KB이고, attach는 그 패인에 대해 B 자신의 `herdr terminal attach`를 돌리며 허브에게서는 패인 id, 크기, 자리를 가져올지만 받습니다. 허브는 리다이렉트 없이, 핸드셰이크 10초, 프레임 최대 256KB로 엽니다. 어느 쪽이든 닫으면 다른 쪽도 끝나고, A가 읽지 않는 동안 B는 attach를 멈춥니다.
- Connect PC 포트는 tailnet 주소(`100.64.0.0/10`, `fd7a:115c:a1e0::/48`)나 loopback에만 엽니다. 어떤 표기든 모든 인터페이스, 그리고 LAN 주소는 시작할 때 거부합니다.
- 허브는 붙은 PC가 보내는 것을 필요한 만큼만 읽습니다. JSON 응답은 8MB(오류는 64KB, 탐색 probe는 16KB)에서 끊고 본문을 다 받을 때까지 타임아웃이 유지되며, 파일은 밝힌 크기, `HERDR_WEB_MAX_TRANSFER_MB`, 크기를 밝히지 않으면 1GB에서 끊습니다. 계속 보내는 PC는 끝까지 읽지 않고 오류로 끊습니다. 붙은 PC(또는 탐색 중인 PC)가 리다이렉트로 답하면 따라가지 않고 오류로 거부하므로, 다른 주소로 허브를 보낼 수 없습니다.
- Connect PC 포트는 `tailscale serve` 뒤가 아니라 tailnet 주소에 직접 엽니다. 이쪽이 더 안전합니다. 요청한 주소는 커널이 WireGuard로 인증된 상대에게서 정하므로, 이 PC든 다른 곳이든 어떤 프로세스도 허용된 PC인 척할 수 없습니다. Serve 뒤에 두면 증명이 헤더가 되는데, 그것은 Serve만 그 소켓에 닿을 때만 성립하고 **이 PC의 아무 프로세스나, 어느 사용자로든 그 헤더를 위조할 수 있습니다.** tailnet 안에서는 WireGuard가 이미 암호화하므로 평문 HTTP로 충분합니다. HTTPS는 service worker와 passkey가 보안 컨텍스트를 요구하는 화면에만 필요합니다.
- 허용한 PC는 이 PC 화면에 앉은 사람이 할 수 있는 일을 할 수 있습니다: 터미널(텍스트·키), 서비스 계정이 읽을 수 있는 파일(위의 로그인 키는 제외), AI 계정 전환. **허용한 PC의 모든 프로세스가 이 PC의 터미널에 입력을 보내고 파일을 읽을 수 있습니다 — 이 PC의 셸 권한과 같습니다.** 확인하는 것은 프로그램이 아니라 PC의 주소이므로, 이 PC의 셸을 줘도 되는 PC만 허용하세요. 내 PC만 허용하세요. `HERDR_WEB_PEER_LOGINS`만 쓰면 그 계정의 모든 기기가 들어오므로, 기기까지 좁히려면 `HERDR_WEB_PEER_ADDRESSES`를 함께 쓰세요.
- 이 방식의 파일 읽기는 어떤 패인 기록에도 흔적을 남기지 않고, Herdr 세션이 하나도 없어도 동작하며, 회선 속도로 전송됩니다. 터미널을 통한 복사에는 없는 성질입니다.
- 일반 파일만 제공합니다. 디렉터리, 장치 파일, FIFO는 논블로킹으로 연 뒤 거부하므로 named pipe가 서버를 멈추게 할 수 없습니다. 파일은 항상 `attachment`와 `application/octet-stream`으로 제공하며, 다운로드는 기본적으로 크기 제한이 없습니다(`HERDR_WEB_MAX_TRANSFER_MB`로 제한 가능). 크기를 0으로 보고하는 파일(procfs, sysfs)은 길이 없이 스트리밍하며 1GB에서 끊습니다.
- 다운로드는 30초 후 만료되는 1회용 티켓으로 받으므로 파일 경로가 URL에 남지 않습니다. 다만 디렉터리 경로와 대상 서버는 탐색 요청 URL에 실리므로 HerdRabbit 앞단의 역방향 프록시 로그에는 기록됩니다.
- 저장된 파일은 `0700` 디렉터리 안의 `0600` 파일이며, 항상 `attachment`와 `application/octet-stream`으로 제공해 업로드된 HTML이나 SVG가 브라우저에서 실행되지 않습니다.
- 업로드는 기본적으로 크기 제한이 없지만 `Content-Length`를 반드시 보내야 합니다. `HERDR_WEB_MAX_TRANSFER_MB`로 제한을 두면 더 큰 업로드는 본문을 읽기 전에 이 헤더만 보고 거부합니다. 업로드는 데이터가 계속 오는 한 오래 걸려도 되고, 2분 동안 한 바이트도 오지 않을 때만 끊습니다. 업로드 폴더 전체에는 용량·개수 제한이 없어 디스크 용량이 유일한 한계입니다.
- 파일을 한 요청으로 받기 위해 본문 수신 타임아웃을 모든 경로에 대해 2분으로 늘렸습니다. 헤더 타임아웃은 그대로라 헤더를 느리게 흘리는 공격은 계속 차단되지만, 본문을 느리게 흘리는 경우는 차단되지 않습니다.
- VAPID 비밀 키와 Push 구독 URL은 해당 OS 사용자만 읽을 수 있는 `0600` 파일에 저장합니다.
- 저장한 AI CLI 로그인은 CLI 자신의 인증 파일 사본이며 `0700` 디렉터리 안의 `0600` 파일입니다. 이 디렉터리와 CLI 디렉터리 사이에서 복사되기만 합니다. API 응답, 오류, 로그, 브라우저 저장소 어디에도 토큰은 실리지 않습니다. 계정 API는 이메일, 플랜, 로그인 만료일만 돌려줍니다. 이 머신은 붙인 PC의 로그인을 받지 않습니다. 이 HerdRabbit을 쓸 수 있는 사람은 계정도 전환할 수 있지만, 이미 터미널 패인으로 할 수 있는 일 이상은 아닙니다.
- 로그인 프로젝트에는 비어 있는 디렉터리를 가리키는 명령만 입력됩니다. 1회용 로그인 코드는 입력 기록에 남지 않고, 로그인을 마치거나 취소하면 프로젝트를 닫습니다.
- 브라우저 저장소에는 UI 설정과 현재 창의 서명된 실행 토큰만 저장하며 비밀번호와 터미널 내용은 저장하지 않습니다.
